# 4090 单路采集提速验收

2026-10-19，在现有 Windows / 16 逻辑 CPU / RTX 4090 主机上运行独立端口的真实 BSK + MuJoCo + UE 采集。原在线平台保留。最终完整任务测速没有同时运行其他测试或分析器；主机原有后台负载仍存在。

## 结果与口径

完整抽屉循环成功，物理任务终态时间仍为 128.335 秒。录制边界覆盖 128.36 秒（含终态确认附近的样本），6419 个状态/动作样本、12838 张对应视频图像、25673 条 200 Hz 腕力样本。原历史记录为 6417 个主帧；结束确认速度影响尾部多记录的两帧，没有改变物理任务时长。

| 阶段 | 本次实测 |
|---|---:|
| 启动准备 | 64.50 秒 |
| 正式录制 | 171.64 秒，0.748× |
| 收尾（含队列排空、视频封口、Parquet 和索引） | 10.82 秒 |
| 录制 + 收尾 | 182.47 秒，0.703× |
| 独立录制脚本启动至退出 | 249.59 秒，0.514× |
| 另行完整数据验收及首/中/尾训练读取 | 22.70 秒 |

录制脚本加验收阶段合计约 272.30 秒、0.471×，这是两阶段计时之和，不是重新实测的 `collect_drawer_cycles.py` 冷启动总时间；不包含验证器解释器/依赖导入、批次随机姿态碰撞预检查。不能把 0.748× 描述为包含启动和验收的倍率。

历史 10 月 16 日正式录制为 670.579 秒 / 0.1914×，本次录制速度约提高 3.9 倍；历史完整批次 1121.018 秒 / 0.1145× 包含预检查和验收，与当前独立录制脚本计时范围不同。此次同机 10 秒基线仍为 52.581 秒 / 0.19×，确认此前的主要瓶颈仍存在。

目前尚未达到稳定 1×。400 Hz 物理计算、渲染/读回及同步链路仍有成本，且每条独立任务重新初始化。后续应继续优化物理主线程、Python/native 调用和经完整复位验证的常驻 worker，而不是仅更换 GPU 或减少采样。

## 已应用的改动

1. 统一配置启用软件 H.264 流式编码，直接 RGB → MP4，移除 LeRobot 临时 PNG 往返和结束后集中视频编码；保留 CRF 30 / GOP 2、双路 1024×1024 / 50 Hz。
2. 对流式编码增加有界反压、工作线程故障传播、持续阻塞超时、最终视频包数检查，不使用上游队列满后丢帧的默认策略。修正上游 uint8 平方溢出导致的零图像标准差及图像 count 语义。
3. 脚本启用已有 C++ FK/Jacobian helper；减小背压容量检查的轮询间隔到 2 ms；渲染状态 TCP 设置 TCP_NODELAY。400 Hz 物理、200 Hz 反馈和腕力、模型、接触及轨道物理配置保持原设置。
4. UE 和动力学并行初始化，仍在双方就绪、预热完成后才开启录制。修复关闭 trace 时进度日志引用未定义 pose 的运行错误。
5. 单条、批次和性能脚本支持 `--recording-config`；摘要记录实际配置、启动/录制/收尾/总耗时与各自倍率。所有正式选项在 `space_sim_server/config/recording.json` 管理。

NVENC 在本机可用，但中间版本的短实验未表现出优于软件流式编码的速度，最终默认仍用软件 H.264。该中间实验使用了上游默认 GOP/统计，不能作为最终编码器等画质的严格对照。最终 NVENC 适配器另验证了 1024²、GOP 2、显式 PTS 和统计；其短 GOP 需要关闭 B 帧，并拒绝 GOP 1。没有基于这个冒烟测试声称硬件编码性能达标。

## 数据验收

- 全任务状态顺序、实际拉出约 80.392 mm、压座/闭合/松爪/撤离判据全部通过。
- 所有主帧与采集时数值 SHA256 一致；双相机源帧、会话、时间戳一一对应，零缺帧、零拒收。
- 两路视频全帧解码，时间间隔 20 ms；200 Hz 腕力纳秒时间连续、完整 SHA256 匹配，并核对 50 Hz 对应点。
- 官方 LeRobot 读取首帧、3209 帧和 6418 帧，七维 state/action、1024² 图像以及非零有效图像统计通过。
- 与非原生 FK 基线比较前 10 秒、排除短基线主动 timeout 后改变的命令：关节目标一致，float32 实际状态最大差 1.1921e-7 rad；不是逐位完全一致的承诺。
- 数据目录 83,330,582 字节（约 79.5 MiB），没有外层照片或 LeRobot 临时 PNG。历史原始目录约 186.1 MiB；精简保存已在前一轮完成，本轮主要优化速度。

回归覆盖流式背压/故障/统计/时间戳、录制、精简数据、配置、脚本、原生几何和 TCP 传输。相关专项全部通过，Ruff 与变更空白检查通过。没有修改 UE C++ 或重新编译插件，没有进行公网部署或重启原在线平台。
