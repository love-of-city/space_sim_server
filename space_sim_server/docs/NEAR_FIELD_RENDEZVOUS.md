# 100 m 内交会与连续任务接口

本页描述 `simulation/near_field/` 的当前实现。分工与需求以[10/15 人工补充](https://applink.feishu.cn/client/chat/open?openChatId=oc_d18831213328163e9a80d6357f61bacc&position=112)、[近距方案](https://lcnrp8hlo6f2.feishu.cn/docx/NXYMdMUW5oFKqSxYjUlcQpZnnid)及[靶点方案](https://lcnrp8hlo6f2.feishu.cn/docx/UQEFdWjQUoAW9wxMt4GcFP5cnMh)为准。

当前能力为实际多体动力学上的参数化导航、机械臂控制及逻辑捕获。双目没有处理真实左右图像或 PnP；`CaptureHold` 没有创建焊接约束、物体附着或载荷传递，不代表实际对接完成。

## 入口与交接

原工作台只有三种起始条件：直接机械臂操作、7 km 交会、300 km 在轨初态。连续任务自动执行远距 → 近距 → 原操作场景，任务编号和固定“末端六维遥操作”面板保持不变。独立 `--fixture` 是惯性系诊断，`--orbital-fixture` 是轨道系 110 m 数值验收初态；两者均不证明远距任务通过，不作为第四个工作台入口。

近距接收 `spacesim-near-field-handoff/1`：上游必须 `accepted=true`，源模型 SHA256 一致。接续包含实际 J2000 位置/速度、姿态/角速度、标量关节位置/速度、飞轮动量、导航后验/交叉协方差、环境随机状态和在途 GNSS 包。只在初始化后、第一步积分前恢复物理状态；之后不得覆写状态制造轨迹。

轨道入口为目标 V-bar 坐标中的 100—125 m、横向偏移不超过 5 m、旋转系速度不超过 0.2 m/s、角速度不超过 0.05 rad/s；当前远距交接要求机械臂与目标铰链位于作者零位。V-bar 为沿轨方向，不能把它误称为径向。

`navigation_reference` 区分装配质心和本体原点。质心到原点转换同时处理姿态杠杆臂与角速度；相对协方差为两星边缘协方差之和减去两个交叉项。不得在阶段切换时重置状态、协方差或随机种子。

## 动力学与时钟

- 使用团队 `sarm_ground_target_self_collision.xml`：服务星装配 169.398546 kg、目标 10 kg。后者仍是团队地面验证模型的仿真假设。
- `LocalMujocoStepper` 是唯一多体积分器；近距外层 20 Hz，内部 240 Hz，逐子步调用 Basilisk 引力。遥操作遵循团队 400 Hz 动力学、100 Hz IK、200 Hz 腕力和 50 Hz 图像采样配置，不能混用时钟。
- `mission_options.orbital_physics` 在远距、近距、遥操作之间保持一致。新连续任务显式使用团队 J2；历史缺省交接恢复点质量。模型参数及太阳间接项由同一套原生 BSK 场计算，导航仅输入估计位置及公开星历。
- `navigation_gravity.py` 使用独立查询消息。迟到观测回溯预测不能回拨真实动力学的星历消息、施力时刻或力缓存。
- 阻力使用 BSK 指数大气与 SPICE 地球旋转状态；太阳光压、食和独立随机外力沿用远距参数及随机流。面积、Cd、密度是工程假设，不是已标定硬件参数。
- 观测时间来自物理消息发布时间；控制预测时间可以晚一个外层步，二者分别记录。位置 m、速度 m/s、时间 s；采集主时钟为整数 ns。

## 几何与距离

| 量 | 定义及当前用途 |
|---|---|
| `dCOM` | 两星实际装配质心间距；机械臂展开后会变化 |
| `dBG` | 服务星本体原点到目标抓取 site 的模长 |
| `sBG` | 以上向量沿抓取面法向的分量，另需报告横向分量 |
| `h` | TCP 到抓取面的轴向间隙；正数表示尚未到达 |
| 相机深度 `Z` | 标志在校正相机光轴上的分量，区别于上述距离和光心斜距 |

当前工程定义取 **收拢零位 TCP 到目标抓取参考面的轴向间隙 h=0.5 m**，作为展开机械臂之前的稳姿条件。用户授权按现有模型确定此定义；它不是已获得团队签署的参考点约定，也不是两星质心距或本体原点距。

`approach_plan.py` 从原始模型 FK 计算收拢 TCP 和抓取法向，保持目标抓取点 y=0.10、z=0.30 m，再求满足 h=0.5 m 的 x。当前结果约 `[0.8949982,0.10,0.30] m`，`dBG≈0.949222 m`；收拢 TCP 约 `[0.3950006,-0.0249963,0.0950012] m`。目标零位抓取 site 为 `[-0.3745,-0.07242,0.04707870013] m`。所有参考点及距离随模型 manifest、任务报告和遥操作交接保存。

本体网格上包络约 z=0.0691 m，抓取点 z=0.30 m 留出高度。预抓取 TCP 沿法向退让 0.15 m，末段代理点退让 0.018 m，均通过原关节限制求解。几何检查覆盖两段路径的 402 个静态姿态、两相机共同视场和 FK 误差；完整动力学另要求整个近距过程无非计划接触。静态采样不等同于连续碰撞证明，逻辑代理也不建立真实锁定。

## 观测与控制

连续任务 GNSS 参数见 `gnss_config.py`：默认 10 Hz；单星每轴 σp=1/√3 m、σv=0.002/√3 m/s，短基线相对残差每轴 σp=0.03 m、σv=0.0015 m/s，界面时延范围 0—0.25 s。它是相关定位结果模型，保留联合协方差，不解算原始码/载波模糊度，也不由 GNSS 解算姿态。独立 fixture 保留自身明确标注的旧传感器配置。

当前双目固定在本体上方，尚未替换为团队腕部双目：光心 B 系 `(-.10,-.10,.34)`、`(-.10,-.10,.46) m`，光轴 B 系 +X，基线 0.12 m；参数为 1920×1200、焦距 1739.13 px、80 mm 标志、0.2 px 视差噪声、10 Hz、0.15 s 延迟。参考为 Basler a2A1920-51gcBAS 与 Kowa LM6HC 地面工业规格，不代表空间鉴定或装入原质量模型。

左右共同视场、16 px 边缘、Z>0.1 m、标志≥8 px、视差≥2 px时生成参数化观测。`visual_ready` 表示当前视觉就绪：至少10个不同采样历元连续通过 EKF 接受、NIS及质量检查，标志≥24 px、深度 σ<0.03 m、后验位置主轴 σ<0.04 m，最近观测年龄≤0.35 s。拒收、质量中断、更新中断、过期或当前协方差超限会撤销就绪并重新累计。它不表示视觉相对 GNSS 的信息贡献比例；GNSS 全程继续融合。历史报告中的 `visual_dominant` 标签只按旧质量状态解释。

轨道近距采用组合质心、目标减服务星的 TNR 坐标：T沿轨、N轨道法向、R径向向外，`rho=Q.T@(r_target_COM-r_chaser_COM)`，服务星位于目标后方时沿轨 `s>0`，接近时 `s_dot<0`。速度扣除轨道系旋转项；近距 EKF 对外仍保持本体原点/J2000。制导边界从原模型质量、当前编码器及带历元合作遥测计算质心杆臂、旋转杆臂和关节运动速度，并变换继承的协方差，不重置滤波器。旧在途包缺少角速度/铰链速度时等待新合作遥测，不从当前物理真值补齐。

`FarHandoff/NearAcquire` 先制动、稳姿并在本次交接沿轨位置附近归线，参考归线速度≤0.02 m/s。横向误差<0.10 m、旋转系速度<0.002 m/s、位置主轴 σ<0.05 m，双星指向均<1°、相对轨道系角速度均<0.001 rad/s、机械臂收拢、铰链稳定、链路和合作几何有效，连续5 s后放行；600 s超时锁存SafeHold。指向/角速度连续稳定2 s后允许采用原稳态过程噪声，不因阶段名保留机动噪声。

|节点|参考点|估计位置误差/旋转系速度|附加放行条件|连续驻留/总等待|
|---|---|---|---|---|
|`Vbar50m`|质心沿轨50 m，横向零|<0.10 m / <0.002 m/s|位置 σ<0.05 m；不要求视觉|5 s / 300 s|
|`Optical17p4m`|严格质心V-bar与光学深度17.4 m的交点|<0.05 m / <0.002 m/s|位置 σ<0.05 m；不要求视觉有效或就绪|5 s / 300 s|
|`VisualReady5p5m`|严格质心V-bar与光学深度5.50 m的交点|<0.02 m / <0.002 m/s|当前视觉就绪、位置 σ<0.04 m|5 s / 60 s|
|`PlatformStandoff`|原收拢TCP抓取面间隙0.5 m|原平台误差及间隙误差均<0.006 m / <0.002 m/s|视觉就绪、新鲜视觉及原导航门限|进入前5 s，进入后保留原5 s驻留 / 300 s|

每点共同要求双星指向、相对轨道角速度、链路、走廊与制动条件有效。任一联合条件中断清零连续驻留，总等待不清零；每节点仅正常通过一次。20 Hz下以101个采样点及实际5 s跨度判定。最终制动/捕获另有300 s上限，巡航不计入。17.4 m检查放行后继续GNSS引导，避免在精确8 px边界（约17.3913 m）之外等待视觉的死锁。

入口放行至5.50 m联合驻留完成前，参考始终为 `[s,0,0]`。光学节点通过模型杆臂/FK求交，不沿用带抓取偏置的旧检查点。零位校核约为 `s=17.65336 m` 和 `s=5.75336 m`；最终平台质心参考约 `[1.24836,-0.10961,0.56096] m`，运行值按模型求得。

只有5.50 m所有条件连续5 s后才启动抓取横向偏置。沿轨参数归一为 `u`，横向参考采用 `10u³-15u⁴+6u⁵`，位置、速度和加速度从同一曲线求导；光学深度2 m时完成偏置，那里不新增例行停泊。之后平滑接回原0.5 m平台驻留和机械臂流程。

参考采用解析分段恒加加速度曲线，节点前制动至零速度、零加速度，放行后重新加速。速度上限按剩余距离为0.10/0.02/0.005 m/s，当前各段保守采用0.10、0.10、0.02、0.0047 m/s；末段降速为完整三维偏置速度预留余量。正常参考加速度≤0.002 m/s²、加加速度≤0.002 m/s³。旋转系PD为 `Kp=0.06 s^-2, Kd=0.6 s^-1`，换算推力时各计一次差分引力、科里奥利、离心与角加速度，原执行器合力范数≤25 N。

主段横向走廊为 `min(1,max(0.10,0.01*s)) m`，检查横向误差加3σ；偏置段相对偏置路径检查。每周期评估含速度/位置不确定度、观测年龄、控制/执行延迟与加加速度制动建立时间的停止距离。无有效视觉不得越过光学深度12 m，无视觉就绪不得越过5 m，提前制动等待最多60 s。正常停泊参考本身不是禁止到达的硬边界。5.50 m放行后就绪失效立即锁存SafeHold。故障制动参考一次生成并停止到可达位置，不返回故障瞬间的位置、不自动恢复。

相对六状态 EKF 保留估计引力梯度、已施加控制、Joseph更新和原时延补偿。超过0.35 s的观测拒收，GNSS/视觉NIS门限30/20。理想姿态、合作目标遥测和编码器仍是仿真假设。近距工程参数集中于 `parameters.py`，完整写入报告和既有近距计划元数据。正常预算3600 s，超时不产生成功交接。

新增 `near_guidance` 记录TNR状态/参考、子段、节点、联合条件、总等待、连续驻留、偏置进度、走廊与制动裕量、故障及保持验证状态；原 `relative_navigation` 语义不变。`vbar_acceptance.json` 从20 Hz物理状态、原模型质量/FK及原始观测复核四节点、质心走廊、视觉就绪、指向/链路和参考连续性，纳入正常成功判定。进入SafeHold本身不证明保持安全，导航/推力不足以验证时报告未验证，不能生成可接续的成功交接。

状态顺序为 `FarHandoff → GNSSApproach → VisualFusion → VisualApproach → PlatformHold → ArmDeploy → ArmAlign → FinalApproach → ContactProxy → Grasp → CaptureConfirm → CaptureHold`。接触代理条件为 `0.012<h<0.021 m`、横向<5 mm、角误差<1°、平台速度<3 mm/s且视觉有效；手指到位与持续确认只建立逻辑标志。

失视觉、失链、协方差过大、IK失败或抓取窗口失效会锁存 `SafeHold`，禁止继续闭合，不自动恢复。故障运行至少保持20 s，并等待估计速度<1 mm/s持续5 s才结束；独立终态验收仍要求实际速度<3 mm/s。通过故障保持验收也不能自动推进到下一阶段。

## 协作交付与验证

近距状态中的 `t`、`sim_time_s` 为继承远距历元的累计任务时间，`elapsed_s` 为近距阶段用时。UE 近距录制沿用阶段时钟，HUD 明确标为 `near elapsed`；网页交会遥测显示累计时间，两者相差输入交接历元。该显示区分不改变物理时钟、观测历元或录制格式。接续原操作场景后，场景时钟从零开始，交接历元仍保存在场景来源中。

张怿心负责 V-bar、CW 及停泊计划，席梓杰负责 PnP 和目标姿态，李一辉负责腕部双目，刘丹旭负责抓取机构；王镱溥负责远距、差分 GNSS、参数同步与仿真合并。现有工程停泊参考点已在上文明确；后续团队方案若改变参考点，应调整计划并重新验证。仍待接带曝光历元的左右图像和标定、带坐标及协方差的 PnP 位姿，以及真实机构几何/接触/锁定/载荷条件。三爪工程草图是设计输入，不能视作当前两指模型的实物等价物。

使用已有云端仿真环境，在服务端目录运行：

```powershell
& $env:SPACE_SIM_PYTHON -m simulation.near_field.run --handoff <已接受远距任务>/handoff.json --output-dir <本次临时输出>
& $env:SPACE_SIM_PYTHON tools/verify_near_field.py --run <本次临时输出> --output <本次临时检查JSON>
```

具体参数以 `--help` 为准。`--orbital-fixture` 验轨道系近距；`--fixture` 仅保留惯性诊断，不能用于V-bar验收；`--vision-loss-phase VisualApproach`、`FinalApproach` 或 `Grasp`、`--communication-loss <elapsed seconds>`用于故障注入。独立检查必须覆盖初态连续性、时间戳、协方差、真实末端误差、接触及停止行为，再做原工作台 UE、控制、采集与数据回读。本次实现及验收记录见[根归档](../../archive/2026_10_20_近距Vbar与停泊点.md)。
