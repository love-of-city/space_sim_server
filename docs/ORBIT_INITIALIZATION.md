# 沿当前圆轨道随机初始化位置

更新：2026-09-08。

## 使用方式

在网页“场景实例”面板中勾选 **沿当前圆轨道随机初始位置**，然后点击“生成并启动场景”。

- 默认不勾选，以兼容旧场景的 180° 起点。
- 开启：沿当前圆周均匀抽取 `[0, 360)` 度的初始轨道相位。
- Seed 留空：创建场景时生成新 Seed；同一 Seed 和开关可复现相同起点。
- 独立于“固定基准 / 训练随机化 v1”：可以固定抓取布局、只随机轨道起点。
- 场景启动后选项锁定；刷新页面、重新连接视频、切换相机不会重新随机。
- 实例摘要显示实际起点（显示保留两位小数，JSON 保存完整精度）。

这里移动的是卫星、机械臂及其周围抓取目标的整体轨道位置，不是只改变被抓取目标的几厘米局部偏移。当前轨道仍是地表上方 500 km、倾角 51.6° 的圆轨道，RAAN、近地点幅角和轨道半径保持不变。随机起点有助于从不同位置观察地球；它不强制选择夜侧，也不保证某一相机总能拍到地球。

## 数据契约与复现

创建请求 `POST /api/scenes/instances` 或 `POST /api/scenes/start` 增加可选布尔字段：

```json
{
  "template_id": "spacecraft-arm-teleop",
  "randomization_profile": "training-v1",
  "seed": 42,
  "randomize_orbit_phase": true
}
```

`/api/scenes/catalog` 的 `defaults.randomize_orbit_phase` 为 `false`。API 拒绝字符串、数字或 null 充当此布尔选项。

实例仍采用 `space-arm-scene-instance/1`：

- `randomize_orbit_phase`：保存本次生成选项。
- `environment.orbit.true_anomaly_deg`：保存实际抽到的真近点角；当前圆轨道下它表示圆周相位。
- `seed`：保存实际 Seed；原有 `randomization` 块继续保存局部目标和关节初态。

采样使用版本化独立流 `random.Random(f"space-arm-orbit-phase-v1:{seed}").random() * 360.0`，不消耗原来 `training-v1` 的随机序列，也不受太阳光强或局部随机化方案影响。Episode 元数据保留完整场景实例及上述字段。

**加载时以保存的角度为准，不重新抽样。** 旧实例缺少开关时按关闭处理，但仍保留已有的显式轨道角；旧实例连轨道信息也没有时使用旧默认值。标记开启却丢失实际轨道角的实例会被拒绝，以免意外用默认角代替已保存的随机起点。

## 动力学与 UE

1. 后端在当前轨道参数的副本中仅替换 `true_anomaly_deg`。
2. 启动脚本按原链路传递整个实例：`-SceneInstancePath` → `--scene-instance`。
3. 仿真入口 `_apply_orbital_initial_state()` 用 BSK `orbitalMotion.elem2rv` 同时计算位置和速度。
4. 卫星使用新轨道位置；抓取目标使用同一位置加原局部偏移。两者速度都加上对应的新轨道速度，保留原有共同漂移及目标速度偏移。关节状态和目标相对姿态不因这个开关改变。
5. 渲染桥读取同一 MJScene 权威状态，以卫星为浮动原点显示地球和太阳。无新增 UE 独立随机数、模型平移或背景补偿。

本功能不改变仿真历元、地球自转相位、太阳星历、卫星初始惯性姿态或姿态保持参考。不同位置下的地球/太阳相对方向由同一惯性坐标系自然得到。

## 回归验证

- `tests/test_scene_orbit_randomization.py`：默认关闭、同 Seed 复现、四个象限覆盖、局部随机化不受影响、严格 API 类型、实例与 Episode 保存。
- `tests/test_orbital_initial_state.py`：旧实例兼容、已保存角度不重采样、错误配置拒绝、四个象限及随机相位对应的位置/速度、目标/关节布局保持，以及原生 BSK/MJScene 状态消息验证。
- `frontend/tests/scene_orbit_randomization.test.mjs`：开关显示、创建请求、目录默认值、运行锁定与回显、0° 正确显示、空闲轮询不覆盖下次配置。

后端/前端更新后需重新启动后端并刷新网页，再生成新场景。已有场景实例不会被追溯修改，UE C++ 无需因本功能重新编译。
