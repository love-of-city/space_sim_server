# 全局自由相机输入与排障

## 适用范围

服务端前端的 Pixel Streaming **主视口**（默认 `BskRenderer`）。总览和腕部视频是模型固定安装相机，不会随玩家自由相机移动。自由相机只改变 UE 玩家视点，不发送机械臂动作，不改变 BSK/MJScene 动力学和权威相机采集。

## 操作

- `C`：进入/退出全局自由相机。进入时请求锁定鼠标；画面提示会区分“鼠标已锁定”和“鼠标未锁定”。未锁定时请点击视频画面重试，而不是继续向桌面边缘移动。
- 鼠标：观察，固定每单位浏览器相对位移 `0.12°`，上下、左右均可连续旋转，没有角度边界，允许越过头顶/脚下并翻转。
- `W/S`：沿当前视线前进/后退；`A/D`：左右移动。
- `Q/E`：仍沿世界竖直方向下降/上升；`W/S` 和 `A/D` 始终跟随当前视线和画面右方，包括翻转后的姿态。
- 平移基础速度 `1 m/s`；按住 `Shift` 为 `5 m/s`。斜向不会额外加速。
- `C`、`Home`、`Esc`、鼠标解锁、页面失焦/隐藏或表单获得焦点：清空按键并返回主视角。

机械臂操作模式中的 `Shift` 仍用于切换末端姿态控制，和自由相机的加速模式互斥。

## 旧路径的问题

1. 前端本地翻转自由相机布尔值，然后依赖同一次 `C` 事件经 SDK 到 UE 再翻转一次。任何丢键、重复键、失焦或仅前端退出都会使两端状态分离。
2. 当前锁定的 Epic SDK 0.2.5 的 `KeyboardController` 优先读取旧 `keyCode`，并丢弃 `229`。中文输入法组合输入可以有正确的 `event.code`，但 `keyCode` 为 `229`。这既可能丢移动键，也可能让页面显示“自由视角”而 UE 仍停留在轨道观察模式。
3. SDK 的 `InputCoordTranslator.translateSigned()` 按视频显示尺寸/纵横比归一化相对鼠标位移，再由 UE 还原；UE 原配置还开启鼠标平滑和 FOV 缩放。这些额外处理不适合作为稳定的浏览器自由相机增益。
4. 原来的失焦/隐藏处理仅在 `operationActive` 时执行；单独进入自由相机不一定满足这个条件。

## 当前链路

```text
浏览器物理 event.code + pointer-lock 相对位移
  → frontend/free_camera.js（完整键状态、鼠标位移累加）
  → PixelStreaming.emitCommand({ BskCameraInput: JSON.stringify(payload) })
  → 主 Streamer 的 SetCommandHandler("BskCameraInput")
  → ABskCameraPawn::ApplyRemoteCameraInput（Game Thread）
  → 只应用玩家相机位置/旋转
```

`payload` 必须包含 `version: 1`、`active`、`forward/right/up`、`boost`、`look_dx/look_dy`。启用时名义 60 Hz 发送完整状态和心跳；按键变化立即发送。`active` 是目标状态，不是切换指令，重复进入/退出不会再次翻转。

- 移动键使用 `event.code`，不受输入法字符转换影响。
- 所有相机控制键在页面捕获阶段消费，不再同时送进 SDK 原生按键输入。SDK 键盘设施只保留其他 UE 快捷键；SDK 鼠标输入始终关闭，避免两条鼠标路径叠加。
- 优先请求 `unadjustedMovement: true` 的原始相对输入，避免把系统加速重新带入鼠标观察。**仅在浏览器明确返回 `NotSupportedError` 时回退普通锁定**；普通锁定可能受系统/RDP 指针速度及加速影响，页面会标明“兼容输入”。不根据服务端的 RDP 会话推断客户端鼠标能力，不在一次操作中自动切换输入增益。
- 锁定成功后的第一份位移只用于丢弃锁定/回中跳变；单事件位移向量长度超过 `256` 个浏览器单位、事件/缓冲超过 `200 ms` 或消息位移溢出 `±4096` 时丢弃异常输入，而不是钳制成一个仍然很大的转角。正常样本按原值发送，不平滑、不加速、不按 FOV/画面大小/帧时长缩放。这些是异常样本保护，**不是累计视角的角度边界**。极快的真实大幅单事件也可能触发保护，可用诊断记录核对。
- 锁定请求去重，同时处理 Promise 拒绝和旧式 `pointerlockerror`；退出/失焦后异步到达的锁定不会再次困住鼠标。
- 自由视角使用相机局部轴上的四元数连续积分，保留翻转后的姿态；不再累加并钳制欧拉俯仰角，也不强制回正地平线。自由模式直接驱动相机 Pawn，并暂时关闭 Pawn/Camera 对 `ControlRotation` 的跟随，避免 UE 内置俯仰/滚转限制再次截断视角。退出时恢复主视角及原控制方式。
- UE 对每份鼠标位移只应用一次，移动按 `速度 × 渲染帧时长` 积分，且远程相机模式不叠加原生按键/轴兜底。
- 离开、切换视频和断流时发送零输入与 `active: false`。若消息无法送达，UE 在最后一个有效包后超过 `0.5 s` 未收到心跳时返回主视角，避免持续漂移。
- 服务端默认主视角仍持续更新，退出自由相机时恢复到最新主视角，而非旧的初始坐标。
- 只在主 Streamer 注册命令，不在模型相机流上假装自由移动。原生 UE 窗口的本地键盘操作仍保留。

## 验证与生效

- `npm --prefix frontend test`：相对鼠标位移、尺寸变化、输入法键码、按键互斥、重复切换、失焦、解锁、视频生命周期和表单输入回归。
- `npm --prefix frontend run build`：更新后端实际提供的 `frontend/dist`。
- UE 自动化 `BskUnreal.Camera.*`：严格参数解析、不同帧率/事件批次下的相同位移、实际 Pawn 平移与旋转、上下/左右正反向连续两圈、极点附近转动、UE 相机管线限制隔离、主视角保护和超时恢复。
- 首次引入 `BskCameraInput` 需要配套 UE 插件；此次输入回归修正保持既有协议不变，已有新版插件时只需刷新前端，不必重启正在运行的仿真。

自动化测试不等同于用户浏览器、网络和 GPU 下的实机手感验收。若仍感觉跳动，应同时观察实际呈现 FPS 与网络延迟；固定输入增益不能消除低帧率或传输卡顿。


## 2026-09-08：输入模式回归及撤回

上一轮依据**服务端处于 RDP 会话**，推测原始输入与桌面边缘有关，于是将所有浏览器强制切换为普通锁定。该推断没有经过实体鼠标输入验证，也不能由服务端的会话类型推出客户端输入能力。用户随后反馈灵敏度不稳定和视角乱飞，因此已撤回这一默认策略。

已证实的代码风险是：普通锁定引入了经过系统处理的位移，而旧缓冲只把每包钳在 `±4096`，不区分正常移动和鼠标回中大跳变。注入 `(1200,-800)` 这样的回中形状样本时，旧代码会将其原样送入 UE，产生约 `173°` 的瞬间旋转。**这是注入样本复现，不是声称已录到用户实体鼠标的这条数据。**

当前优先原始输入，只在明确不支持时回退；增加锁定首样本、异常跳变和陈旧缓冲保护。UE 局部轴四元数无限旋转逻辑、固定 `0.12°/单位` 的正常输入增益和模型/动力学均未改变。

本次验证：

- 前端测试覆盖 raw 默认策略、受限回退、锁定首帧、正反回中跳变、不同事件频率/批次下的同一位移、陈旧数据和退出清理。
- 独立 GPU UE + Pixel Streaming + Edge 实测，可信浏览器事件注入的大跳变及反向跳变不会进入相机旋转；正常水平/垂直正反各 `720°`、`W` 平移和 `Home` 返回通过。
- 本次串流测试使用独立 UE 相机实例，没有连接或重启用户当前 SARM 仿真；结果保存在忽略目录 `run/camera-regression-20260908/verified/`。
- **验证边界**：CDP 输入不等同于实体 RDP 鼠标。不再把“能连续注入位移并转两圈”当作物理桌面边界已经消失的证明；网页不能补出设备没有提供的相对位移。原来的实体输入边界需要结合浏览器诊断继续确认。

## 当前浏览器鼠标诊断

页面提供只读函数，可在浏览器控制台读取，不需要 UE 重启或打开探针：

```javascript
window.__freeCameraDiagnostics()
```

包含实际锁定状态、`inputMode`（`raw` / `compatible` / `unlocked`）、已接纳/丢弃数量、陈旧批次数，以及最近最多 64 份鼠标样本及处理原因。仅记录该页面自由相机锁定期间的相对鼠标输入，不记录其他程序输入或提供可写相机状态。统计里的 accepted 是进入发送缓冲的样本；缓冲随后仍可能因陈旧/溢出被整体丢弃，不等同于 UE 已确认收到。

## 可重复的串流回归与只读诊断

仅在**独立测试实例**中启动 UE 并附加 `-BskCameraDiagnostics`，使用专用信令、后端、数据目录和端口，不要连接操作员的运行中场景。该开关在主 Streamer 注册只读 `BskCameraProbe` 命令，通过 Pixel Streaming `Response` 返回累计输入、自由模式状态、Pawn/Camera/最终 POV 四元数；不开此开关不会开放探针。

在服务端仓库根目录执行（Node 22+、本机 Edge；账号来自独立测试后端）：

```powershell
$env:BSK_CAMERA_TEST_URL = 'http://127.0.0.1:18000/'
$env:BSK_CAMERA_TEST_USER = '<测试账号>'
$env:BSK_CAMERA_TEST_PASSWORD = '<测试密码>'
node scripts/verify_free_camera_runtime.mjs
Remove-Item Env:BSK_CAMERA_TEST_URL,Env:BSK_CAMERA_TEST_USER,Env:BSK_CAMERA_TEST_PASSWORD
```

脚本使用独立无界面浏览器配置目录，通过真实页面按键和可信浏览器鼠标事件驱动实际相机；会断言锁定、原始输入选项、注入的正反异常跳变丢弃、双向两圈、全链路位移/姿态、移动/退出和视频解码。报告与截图默认写入忽略目录 `run/free-camera-runtime/`，可用 `BSK_CAMERA_TEST_OUTPUT` 改目录。UE 和后端的测试启动/关闭由调用方负责；脚本只关闭自己启动的浏览器。
