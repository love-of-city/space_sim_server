# CubeSat + SO-101 组合模型制作说明

## 1. 任务目标

本任务需要把 MuJoCo Menagerie 提供的 SO-101 机械臂安装到一个自由漂浮的
CubeSat 上，生成能够同时被原生 MuJoCo 和 Basilisk `MJScene` 加载的 MJCF
模型。

最终模型需要满足以下要求：

1. CubeSat 与机械臂属于同一棵多刚体树，而不是两个独立场景。
2. 整个组合体只有一个连接惯性空间的自由关节。
3. 机械臂关节运动能够对卫星本体产生真实的反作用。
4. 保留 SO-101 的质量、惯量、关节限位、碰撞体、夹爪和腕部相机。
5. 机械臂使用直接关节力矩接口，而不是原模型的内置位置伺服器。
6. 上游 Menagerie 模型保持不变，组合模型可以确定性地重新生成。
7. STL 路径既适用于原生 MuJoCo，也适用于 Basilisk 的虚拟文件系统。

第一阶段交付组合模型。后续抓取阶段已增加独立自由目标、六关节控制器和完整
Basilisk 示例场景，见第 12 节；仍不包括推力器、反作用轮或视觉闭环控制。

## 2. 输入模型审计

上游模型位于 [`assets/robotstudio_so101/`](../assets/robotstudio_so101)，来源为
[MuJoCo Menagerie 的 Robot Studio SO-101](https://github.com/google-deepmind/mujoco_menagerie/tree/main/robotstudio_so101)。

审计得到以下结论：

- 模型入口是 `so101.xml`，`scene.xml` 和 `scene_box.xml` 只是带地面或目标方块的展示场景。
- 模型要求 MuJoCo 3.1.3 及以上；本地 Basilisk 使用 MuJoCo 3.11.0，版本兼容。
- `base` 直接位于 `worldbody` 下且没有 free joint，因此原模型是固定基座机械臂。
- 模型包含 8 个非 world body、6 个 hinge joint、6 个 position actuator 和 18 个 mesh。
- 模型已经提供各连杆的显式质量和惯量、机械臂简化碰撞体、夹爪精细接触参数和腕部相机。
- SO-101 总质量为 `0.644006 kg`，其中包括相机安装 body 上由 geom 提供的 `0.012 kg`。
- 原模型使用 `meshdir="assets"` 引用 STL；Basilisk 加载 XML 字符串时仍需显式把 STL 传入 MuJoCo VFS。

因此无需重新建立机械臂，只需改变根部拓扑、执行器语义和资产路径。

## 3. 总体方案

组合采用“源模型只读、脚本生成最终 XML”的方式：

```text
cubesat_bus.xml ──────┐
                      ├─ MjSpec.attach_body() ─> cubesat_so101.xml
SO-101 so101.xml ─────┘
          │
          └─ 位置伺服转换为直接力矩 actuator
```

最终刚体树为：

```text
world
└── cubesat_bus
    ├── cubesat_free
    └── so101_mount_frame
        └── so101_base
            └── so101_shoulder
                └── so101_upper_arm
                    └── so101_lower_arm
                        └── so101_wrist
                            └── so101_gripper
                                ├── so101_camera_mount
                                └── so101_moving_jaw_so101_v1
```

`cubesat_free` 是唯一 free joint。`so101_base` 与 `cubesat_bus` 之间没有 joint，
所以机械臂底座被刚性安装在卫星上；机械臂内部的 6 个 hinge joint 保持原样。

## 4. CubeSat 基线模型

CubeSat 使用参数化 12U 占位模型，默认参数如下：

| 参数 | 默认值 |
|---|---:|
| 外形尺寸 | `0.2263 x 0.2263 x 0.3405 m` |
| bus 质量 | `24 kg` |
| bus 原点 | 几何中心 |
| bus 质心 | `[0, 0, 0] m` |
| SO-101 安装位置 | `[0, 0, 0.17025] m` |
| SO-101 安装四元数 | `[1, 0, 0, 0]`，MuJoCo `w-x-y-z` 顺序 |

默认惯量按均匀长方体计算：

```text
Ixx = m / 12 * (y^2 + z^2)
Iyy = m / 12 * (x^2 + z^2)
Izz = m / 12 * (x^2 + y^2)
```

得到：

```text
[Ixx, Iyy, Izz] = [0.33430388, 0.33430388, 0.20484676] kg*m^2
```

视觉 geom 和碰撞 geom 使用两个独立 box，便于以后分别替换外观 mesh 和工程碰撞体。
默认安装在 bus 的 `+Z` 端面，SO-101 的 `+Z` 轴朝卫星外侧。

这些数值只是工程占位值。用于实际研究前，应替换为真实卫星的质量、质心、
完整惯量矩阵、外形和机械安装变换。

## 5. 使用 MjSpec 拼接模型

生成器 [`build_model.py`](../assets/cubesat_so101/build_model.py) 使用 MuJoCo 官方
Python API `mujoco.MjSpec`，而不是直接用字符串拼接 XML。

处理过程如下：

1. 加载 [`cubesat_bus.xml`](../assets/cubesat_so101/cubesat_bus.xml)。
2. 根据命令行参数更新 bus 尺寸、质量、质心和惯量。
3. 在 bus 上创建 `so101_mount` site 和 `so101_mount_frame` frame。
4. 加载上游 `so101.xml`，在内存中转换 actuator。
5. 使用 `mount_frame.attach_body(arm.body("base"), "so101_", "")` 挂接整个机械臂子树。
6. 对机械臂的 body、joint、geom、site、camera、asset 和 actuator 统一增加 `so101_` 前缀。
7. 把 mesh 目录恢复为相对生成文件的 `../robotstudio_so101/assets`。
8. 编译、验证并输出 [`cubesat_so101.xml`](../assets/cubesat_so101/cubesat_so101.xml)。

名称前缀可以避免以后加入其他机械臂或目标物时发生名称冲突。MjSpec 会自动导入
附着子树引用的 default、material、mesh 和 actuator，不需要复制 18 个 STL。

生成文件带有“自动生成，请勿直接编辑”说明。模型修改应发生在 bus 源 XML、
生成器参数或上游 SO-101 源模型中，然后重新生成最终 XML。

## 6. 执行器转换

Menagerie 原模型使用高增益 position actuator。根据本任务选择，组合模型改为直接
关节力矩输入，保留关节本身的 damping、frictionloss、armature 和位置限位。

每个 actuator 被转换为以下等价语义：

```text
transmission = joint
gain type    = fixed
gain         = 1
bias         = none
dynamics     = none
gear         = [1, 0, 0, 0, 0, 0]
ctrl range   = [-2.94, 2.94] N*m
force range  = [-2.94, 2.94] N*m
```

稳定的 actuator 名称为：

```text
so101_shoulder_pan_motor
so101_shoulder_lift_motor
so101_elbow_flex_motor
so101_wrist_flex_motor
so101_wrist_roll_motor
so101_gripper_motor
```

MuJoCo 的 `<motor>` 本质上是 `<general>` 的快捷形式。MjSpec 序列化后使用
`<general>` 标签，但经编译检查，其 gain、bias、dynamics、gear 和传动类型均与
直接力矩 motor 等价。控制输入单位是 `N*m`，不再是目标关节角。

MjSpec 会把父 default 的设置物化到嵌套 default 中。实现过程中曾发现即使实际
actuator 已经转换，序列化 XML 的 visual/collision default 仍可能残留旧位置伺服
增益。生成器因此同时清理所有相关 default 类，避免未来新 actuator 意外继承
`kp=50` 或 `kp=998.22`。

## 7. 资产路径处理

原始 SO-101 XML 依赖 18 个 STL。最终 XML 使用：

```xml
<compiler meshdir="../robotstudio_so101/assets/"/>
```

这样，原生 MuJoCo 可以从任意工作目录通过最终 XML 路径解析 mesh，同时避免在
组合目录中重复保存约 18 MB 的 STL。

Basilisk 的 `MJScene.fromFile()` 会读取 XML 内容并通过 MuJoCo VFS 编译，因此加载时
仍需传入 STL：

```python
from pathlib import Path

from Basilisk.simulation import mujoco

model_dir = Path("assets/cubesat_so101").resolve()
mesh_dir = model_dir.parent / "robotstudio_so101" / "assets"
mesh_files = [str(path.resolve()) for path in sorted(mesh_dir.glob("*.stl"))]

scene = mujoco.MJScene.fromFile(
    str(model_dir / "cubesat_so101.xml"),
    files=mesh_files,
)
```

## 8. 生成器接口

默认生成：

```bash
uv run --no-project --with mujoco==3.11.0 \
  python assets/cubesat_so101/build_model.py
```

检查已提交 XML 是否与生成结果一致：

```bash
uv run --no-project --with mujoco==3.11.0 \
  python assets/cubesat_so101/build_model.py --check
```

主要参数如下：

| 参数 | 含义 |
|---|---|
| `--bus-size X Y Z` | bus 完整尺寸，单位 m |
| `--bus-mass MASS` | bus 质量，单位 kg |
| `--bus-com X Y Z` | bus 坐标系下的质心，单位 m |
| `--bus-fullinertia IXX IYY IZZ IXY IXZ IYZ` | 完整惯量矩阵，单位 `kg*m^2` |
| `--mount-pos X Y Z` | SO-101 安装位置，单位 m |
| `--mount-quat W X Y Z` | SO-101 安装四元数 |
| `--output PATH` | 输出 XML 路径 |
| `--check` | 只检查，不重写输出 |

生成器会拒绝非正质量、非正尺寸、非正定惯量、零四元数、非 XML 输出，以及覆盖
上游 SO-101 或 bus 源文件的输出路径。未提供完整惯量时自动使用均匀长方体惯量。

## 9. 稳定模型接口

最终模型提供以下关键对象：

| 类型 | 名称 | 用途 |
|---|---|---|
| body | `cubesat_bus` | 自由漂浮卫星本体 |
| joint | `cubesat_free` | 组合体唯一自由关节 |
| site | `cubesat_origin` | bus 原点状态与外力作用参考 |
| site | `so101_mount` | 机械臂安装坐标系 |
| site | `so101_baseframe` | SO-101 基座坐标系 |
| site | `so101_gripperframe` | 夹爪末端坐标系 |
| camera | `so101_wrist_cam` | 上游腕部固定相机 |

Basilisk 中可以通过以下方式取得力矩输入：

```python
actuator = scene.getSingleActuator("so101_shoulder_lift_motor")
actuator.actuatorInMsg.subscribeTo(torque_message)
```

例如 `SingleActuatorMsgPayload(input=0.2)` 表示向该 hinge joint 输入 `0.2 N*m`。
模型不负责由目标角计算力矩，后续必须增加关节控制器。

## 10. 验证方法和结果

### 10.1 原生 MuJoCo 结构验证

生成器每次运行都会编译模型并检查：

| 指标 | 结果 |
|---|---:|
| `nbody` | 10，包含 world |
| Basilisk 可见 body | 9，不包含 world |
| `nq` | 13，即 free joint 的 7 维位置加 6 个 hinge angle |
| `nv` | 12，即 free joint 的 6 维速度加 6 个 hinge rate |
| `nu` | 6 |
| `nmesh` | 18 |
| free joint 数量 | 1 |
| 默认总质量 | `24.644006 kg` |
| 默认构型接触数 | 0 |

同时检查全部 body、joint、site、camera 和 actuator 名称，以及每个 actuator 的
传动类型、增益、bias、activation dynamics、gear、控制范围和力矩范围。

### 10.2 自由漂浮动力学验证

原生 MuJoCo 验证向 `so101_shoulder_lift_motor` 施加 `0.2 N*m`、持续 `0.5 s`
的力矩脉冲，并把总仿真时间推进到 `2 s`。验收条件为：

- shoulder-lift 关节产生可观测运动；
- CubeSat 位姿因内部角动量交换而发生变化；
- `qpos` 和 `qvel` 全部有限；
- 运动过程中不出现非预期接触；
- 系统质心漂移小于 `1e-5 m`。

这项测试确认机械臂不是固定在惯性空间，而是正确安装在自由漂浮 bus 上。

### 10.3 Basilisk 集成验证

最终 XML 和全部 STL 已通过本地 Basilisk `MJScene` 加载。随后以 `0.005 s` 任务步长
运行 `0.5 s`，持续输入 `0.2 N*m` shoulder-lift 力矩，得到：

```text
shoulder-lift 关节位移：0.105838 rad
CubeSat 姿态 MRP 变化：0.002008
```

这证明 Basilisk `SingleActuatorMsg -> MJSingleActuator -> MuJoCo joint torque` 链路有效，
且 bus 能正确表现机械臂运动造成的反作用。

### 10.4 其他检查

- `build_model.py --check` 的确定性重新生成检查通过。
- 自定义 bus 尺寸、质量和安装位置的生成与加载通过。
- Ruff 静态检查和格式检查通过。
- XML 语法检查通过。
- EGL 离屏渲染确认机械臂基座落在 bus 的 `+Z` 端面，零位构型未穿入卫星。

### 10.5 可视化检查

**打开交互式模型**

机器有桌面环境时执行：

```bash
uv run --no-project --with mujoco==3.11.0 \
  python -m mujoco.viewer \
  --mjcf assets/cubesat_so101/cubesat_so101.xml
```

查看器中可用鼠标旋转、平移和缩放，也可以在控制面板里调整关节状态及 actuator 输入。

**生成可视化 PNG**

远程服务器或无窗口环境可用 EGL：

```bash
MUJOCO_GL=egl uv run --no-project \
  --with mujoco==3.11.0 --with pillow python - <<'PY'
from pathlib import Path
import mujoco
from PIL import Image

model = mujoco.MjModel.from_xml_path(
    str(Path("assets/cubesat_so101/cubesat_so101.xml").resolve())
)
data = mujoco.MjData(model)
mujoco.mj_forward(model, data)

renderer = mujoco.Renderer(model, width=640, height=480)
camera = mujoco.MjvCamera()
camera.lookat[:] = model.stat.center
camera.distance = 1.15 * model.stat.extent
camera.azimuth = 135
camera.elevation = -20

renderer.update_scene(data, camera=camera)
Image.fromarray(renderer.render()).save("cubesat_so101.png")
renderer.close()
PY
```

然后打开：

```bash
xdg-open cubesat_so101.png
```

当前模型的离屏 framebuffer 是 `640×480`，直接请求更高分辨率会报错。腕部相机 `so101_wrist_cam` 已保留，但 Basilisk `MJScene` 本身不会直接输出该相机的图像。

## 12. 独立自由目标抓取验证

### 12.1 目标模型与接触方式

抓取模型在原组合体之外增加第二个 top-level body `capture_target` 和 free joint
`capture_target_free`。目标总质量为 `0.10 kg`，由窄圆柱把手和主箱体组成：

| 参数 | 数值 |
|---|---:|
| 把手半径 | `0.004 m` |
| 把手半长 | `0.025 m` |
| 主体半尺寸 | `0.025 x 0.025 x 0.025 m` |
| 目标质心 | `[0.055, 0, 0] m` |
| 目标主惯量 | `[3.349333333e-5, 7.758e-5, 7.758e-5] kg*m^2` |

最终模型有 `nq=20`、`nv=18`、`nu=6`、两个 free joint，总质量为
`24.744006 kg`。目标把手使用 `condim=6` 和摩擦参数
`[1, 0.005, 0.0005]`。模型没有 equality、weld 或 adhesion，抓取完全依赖夹爪
两侧的法向接触与摩擦。

生成 XML 中的目标默认位姿远离机械臂，因此默认构型接触数仍为 0。场景在
`InitializeSimulation()` 后才设置标定任务位姿，避免模型一加载就出现穿透或接触。

### 12.2 控制器与任务时序

场景使用 `0.001 s` Basilisk dynamics task。每个关节采用
`MJJointPIDController.JointPIDController`，`Ki=0`，再串接
`SaturationSingleActuator` 限制力矩。位置和速度参考由 Python `SysModel` 使用五次
smoothstep 同步发布，控制次序为“轨迹、PID、限幅、MuJoCo 动力学”。

| 阶段 | 时间 | 动作 |
|---|---:|---|
| 预抓取 | `0-1 s` | 保持张开夹爪 |
| 接近 | `1-4 s` | 平滑运动到把手对准构型 |
| 稳定 | `4-4.5 s` | 消除接近残余速度 |
| 闭合 | `4.5-6 s` | 夹爪闭合并建立双侧预紧力 |
| 保持 | `6-7 s` | 验证持续接触 |
| 撤离 | `7-9 s` | 机械臂携带目标回撤 |
| 最终验证 | `9-10 s` | 保持抓取并检查相对运动 |

轨迹是已知关节空间轨迹，用于隔离并验证动力学和接触链路；它不是在线 IK，也不
包含视觉测量。CubeSat 和目标初始共同平移速度为 `[0.01, -0.004, 0.002] m/s`，
目标另有本体系 `[1, 0, 0] rad/s` 初始自旋，因此接触前两者保持独立自由运动。

### 12.3 抓取验收结果

完整 `10 s` Basilisk 仿真得到：

| 指标 | 结果 | 验收要求 |
|---|---:|---:|
| 首次接触时间 | `5.479 s` | 不早于 `4.5 s` |
| 最长连续双侧接触 | `3.648 s` | 不小于 `0.5 s` |
| 撤离阶段双侧接触覆盖率 | `100%` | 不小于 `90%` |
| 固定夹爪峰值法向力 | `1.413 N` | 大于 `0.01 N` |
| 活动夹爪峰值法向力 | `1.531 N` | 大于 `0.01 N` |
| 目标撤离位移 | `24.14 mm` | 不小于 `8 mm` |
| 抓取点最大相对漂移 | `2.412 mm` | 不大于 `3 mm` |
| 最终相对线速度 | `0.000222 m/s` | 不大于 `0.005 m/s` |
| 最终相对角速度 | `0.01509 rad/s` | 不大于 `0.05 rad/s` |
| 非夹爪接触 | `0` | 必须为 0 |

这覆盖了接近、首次接触、夹爪闭合、持续双侧抓取和携带目标撤离。主目标箱体没有
撞击机械臂或卫星本体。

### 12.4 动量守恒重建

场景记录 Basilisk `scene.stateOutMsg` 的全部 `qpos` 和 `qvel`。验收程序使用同一
MJCF 在原生 MuJoCo 中逐帧调用 `mj_forward()` 和 `mj_subtreeVel()`，计算：

```text
P        = m_total * subtree_linvel[0]
H_COM    = subtree_angmom[0]
H_origin = H_COM + r_COM x P
```

结果如下：

| 指标 | 最大误差 | 验收上限 |
|---|---:|---:|
| 总线动量 | `2.32e-8 kg*m/s` | `5e-5 kg*m/s` |
| 绕系统质心角动量 | `1.26e-8 kg*m^2/s` | `1e-5 kg*m^2/s` |
| 绕惯性原点角动量 | `1.44e-8 kg*m^2/s` | `1e-5 kg*m^2/s` |
| 系统质心匀速运动 | `2.54e-9 m` | `5e-5 m` |

执行器力矩属于系统内力矩，因此不会改变整个“卫星 + 机械臂 + 目标”系统的总动量。
机械能只作报告，不作守恒断言：PID 会做功，关节 damping、接触摩擦及非弹性碰撞会
耗散机械能。MuJoCo `armature` 是广义质量矩阵中的折算惯量，没有独立定义的空间
转子动量，因此不能额外叠加到上述空间角动量中。

运行方法：

```bash

  python assets/cubesat_so101_grasp/build_model.py --check

uv run --no-project --with mujoco==3.11.0 \

uv run --no-project --with mujoco==3.11.0 --with pytest \

```

的 `qpos/qvel`，不会另行积分一套动力学：


容易遮挡真实的红色细把手，因此默认关闭；仅在接触调试时显式增加
`--contact-debug`。可用 `--fps` 修改输出帧率。

## 13. 已知限制和后续工作

当前模型仍有以下限制：

1. 12U bus 的质量、质心和惯量是占位值，不代表具体卫星。
2. bus 只有 box 外形，没有太阳翼、推进器、反作用轮、天线或对接机构。
3. SO-101 是地面教育机械臂，其关节摩擦、阻尼和力矩上限尚未按空间环境重新标定。
4. 抓取场景已有 PID 关节位置/速度跟踪，但没有在线 IK、阻抗控制或轨迹规划器。
5. 模型保留 MuJoCo wrist camera，但 Basilisk `MJScene` 不直接输出相机图像。
6. 当前目标是标定把手和已知轨迹的回归工况，尚未覆盖任意目标形状、未知初始状态
   或抓取失败恢复。

建议后续按以下顺序推进：

1. 替换真实 CubeSat 质量、质心、惯量和安装参数。
2. 用在线 IK 或任务空间阻抗控制替换标定关节轨迹。
3. 增加目标位姿估计误差、质量惯量不确定性和 Monte Carlo 抓取包络测试。
4. 增加推力器或反作用轮，研究机械臂运动补偿和整星姿态控制。
5. 以 `so101_gripperframe` 和 `so101_wrist_cam` 为接口接入 Unreal Engine 视觉闭环。

## 14. 总结

本任务没有直接修改 Menagerie 的 `so101.xml`，而是通过 MjSpec 把机械臂子树附着到
一个带 free joint 的参数化 CubeSat bus，并把上游位置伺服器转换成受限直接力矩
接口。最终模型同时通过原生 MuJoCo 编译、动力学响应、Basilisk 消息驱动积分和
离屏渲染检查，形成了可重复生成、可追踪来源、可继续扩展的星载机械臂模型基线。
扩展抓取场景进一步证明机械臂可以在自由漂浮条件下接近并纯接触抓住独立目标，
携带目标撤离，同时保持整个封闭多刚体系统的线动量和角动量守恒。
