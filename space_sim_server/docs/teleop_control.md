# 遥操作、关节参考保护与 80% 速度诊断

`zmh_v1` 整合主线的单次速度 IK、输入通道分离和只读速度诊断，同时保留本地已验证的关节参考保护与有界卸载。未引入 Placo 或定制 QP，也不承诺解决所有 IK/接触问题。历史合并说明见
[`2026_09_20_zmh_v1主线整合.md`](../archive/2026_09_20_zmh_v1主线整合.md)。

## 控制链路

```
键盘/手柄 → 原有输入平滑与使能/超时保护 → 一次速度 IK
         → 关节角度/速度限制 → 有界在线抬肘＋腕部向下＋J3负角偏好 → JointReferenceGovernor → 关节参考积分 → 原有物理 PD 控制
```

默认恢复 `ik_pose`。`strict` 作为原有对照模式保留。详细的阻尼/严格模式取舍见
[CARTESIAN_IK_MODES.md](CARTESIAN_IK_MODES.md)。

已移除：分阶段 QP、alpha/beta 进度控制、额外关节加速度约束、边界制动策略、
末端参考领先门槛、求解失败后切换制动、按实测位姿持续纠偏、
重新使能时重设末端目标。这些逻辑不再只是隐藏为非默认，而是从代码和依赖中删除。
OSQP/SciPy 不再是本项目运行依赖；未卸载共享环境中已经安装的包。

松键或指令过期后，立即停止推进关节和末端参考，目标关节速度归零，不额外执行
末端纠偏。例外仅为明确许可的中性输入：`allow_reference_recovery=true` 且指令新鲜、无安全原因时，独立状态机可有界退回过大的关节参考偏差，并同步其正运动学目标。指令过期、急停或退出操作均不授予此许可。实际机械臂仍通过 PD 减速/保持关节位置；不等于瞬时冻结物理速度。

保留：XML 原始角度限位、关节速度上限、关节目标 clip、输入使能/超时保护、
关节 PD 与力矩限幅、物理接触。没有删除任何 XML 关节或碰撞约束。
当前选定模型的限位仍由 `joint_limits.py` 统一读取。

`ik_pose` 使用参考关节速度积分：实测末端位置/姿态只用于诊断，但逐关节跟踪误差和持续力矩饱和由独立参考保护器检查，可能统一缩小整组关节速度。参考末端轨迹由保护后速度推进，不是独立的纠偏目标。速度诊断的报警本身不改变控制输出。
近奇异时阻尼求解仍可能产生侧移/姿态误差，限位也仍可令整个动作停止。
实时环不宣称严格姿态锁定或全局分支搜索。现已加入
[有界在线几何构型偏好](ELBOW_PREFERRED_IK.md)，从零位或任意初态也可逐步改善肘高；
可独立关闭，不是回初始构型，不会在空闲/仅夹爪输入时自行运动。

## 机械臂和夹爪的输入独立

- 实时控制不再向 IK 传入初始关节构型参考；不自动向初始构型靠拢。
- deadman/超时仍为共同授权条件，六维末端输入与夹爪开合各自判断是否有指令。
  只操作夹爪不会启用机械臂 IK，也不会续执行之前的机械臂平滑指令。
- 机械臂无有效输入时跳过 IK/Jacobian/SVD 求解链；除明确许可的有界卸载外，保持关节参考并令目标速度归零。
  （为实测速度遥测计算的雅可比仍保留，未做本轮范围外的采样优化。）
- 机械臂与夹爪有组合输入时同时正常执行；松开机械臂输入后夹爪可以继续开合。
- `ik_solve_count` 只计实际求解次数，空闲 `solve_time_ms=0`，旧残差/原因不会残留。
  参考链的几何诊断保留上一采样值；实测运动、动作序号、夹爪与超时处理仍更新。
- 本轮未调整输入平滑参数或 `dt <= 0.02 s` 的现有时间截断，未取消任何机械限位。

## 80% 监测独立保留

`达成率 = dot(实测末端速度, 指令单位方向) / 输入平滑后、IK 降速前的速度`

- 本体系、`sarm_ee` 控制点；平移 m/s 和旋转 rad/s 分开显示。
- 实测关节角/速度经过雅可比得到末端速度；不使用 IK 预测值冒充。
- 无有效指令、指令过期、缺少实测速度时，不做低速报警。
- .35 s 启动/换向观察；持续低于 80% 达 .30 s 报警；连续达到 85% 达 .20 s 恢复。
  这些计时仅影响提示，不参与 IK、不改变目标、不阻止操作。
- 限位原因来自原有限幅的原始关节速度与实际触发边界，而不是看到某轴靠近边界就猜测。
- 其他证据包括阻尼残差、奇异附近、实际关节跟踪偏差，以及 PID 请求/限幅输出证实的力矩饱和。
- 碰撞原因仍待接触力证据支持；证据不足显示“原因待确认”。

## 使用

新启动场景默认 `ik_pose`，也可显式选择 `--ik-mode strict`。
如果此前设置了 `SPACE_SIM_IK_MODE=constrained`，请清除该环境覆盖或改为 `ik_pose`。
旧模式名不会静默重映射，新进程会给出明确配置错误。
运行中的 Python 场景不能热替换：需要停止并重新启动场景，而非只复位。
前端需要重新构建并刷新；旧场景仍可能发出旧遥测，不能据此判断新逻辑已加载。

```powershell
python -m pip install -e ".[test,simulation]"
python -m pytest tests/test_teleop_target.py tests/test_teleop_channels.py tests/test_simplified_teleop.py tests/test_motion_diagnostics.py tests/test_joint_limits.py
python tools/validate_teleop.py --output run/simplified-teleop-validation/kinematic.json
python tools/validate_teleop.py --physics --adapter-root <适配器目录> --output run/simplified-teleop-validation/dynamics.json
# 可选：--scene-instance <保存的场景 JSON> 或 --ik-mode strict
cd frontend
npm test
npm run build
```

验证工具仅创建独立仿真，不连接现有控制服务/渲染器、不重置运行场景。
物理测试没有完整轨道星历，也不替代实际交互和各种接触场景验收。

## 关节角度与限位显示

右侧「关节角度与限位」显示 J1–J6 的**实际**角度，不含夹爪滑动关节和反作用轮。
角度相对模型零位，以度显示，不按 ±180° / 360° 折返，也不是启动后的累计路程。
`arm_joint_limits_rad` 是仿真从当前模型读取的六组上下限，在会话建立时准备，随既有观察帧发送；
`[null, null]` 表示连续关节，缺失字段表示未知，前端不猜测上下限。
每个关节显示距上下限的剩余角度：≤10° 黄色提醒，≤1° 红色提示，越界另外标示。
这些阈值仅影响显示，不影响 IK 或控制；接近限位不自动判定为卡住原因。
断线、场景停止/重置或超过 3 秒未收到观察帧时清空旧角度。

前端构建后刷新可看到面板；完整上下限需要新版后端及新启动的仿真进程。
旧进程尚未发送/转发限位元数据时只显示实际角度与「限位未提供」，不会套用默认模型的限位。
不要仅复位旧场景来加载代码；请在合适时机重启平台并重新启动场景。

## 指定操作姿态直接启动

默认新场景创建时直接将六个关节设置为指定的操作姿态，不再经过从全零姿态到操作姿态的准备轨迹；旧场景中仍保留的准备标记仅用于兼容读取。
