# SpaceSim 全平台性能剖析与优化

本轮以 `9011b97c9e19939cc984f98c36085f183a27f885` 为基线，覆盖仿真计算、Python 渲染发送、真实浏览器预览和 LeRobot 双相机采集。没有新增产品功能，也未调整模型几何、物理步长、求解精度、控制频率、相机参数或数据协议。此前动画播放时钟优化继续保留。

## 定位结果与实际变更

新版 SARM 的主要计算瓶颈是精细接触碰撞。一次 3 s 仿真剖析中，原生步进用时约 7.956 s，其中碰撞检测 7.552 s、SDF–SDF 碰撞 5.624 s，约占步进的 95% 和 71%；约束求解仅 0.086 s。此处使用诊断计时，不能与无插桩吞吐测试直接混比。增加 MuJoCo 工作线程的试验更慢，未采用。

最终采用四项局部优化：

- BSK 差分引力仍逐刚体、逐引力源调用原生 `computeAccelerationFromSource`，顺序相同；每个引力源只批量转换一次结果数组，减少 Python/NumPy 临时分配。
- 渲染坐标轴为单位阵时，MRP 直接转换为归一化四元数，避免逐刚体反复构造和验证旋转矩阵。保留同一半球及精确 π 转角的符号约定；非单位坐标轴保留原路径，每次检查坐标轴，支持后续修改。
- 螺纹 SDF 使用线程局部、固定容量的精确坐标缓存复用 `hypot/atan2`，保留带符号零；每种模式复用最近一次完全相同的梯度查询。仅当端盖严格超过径向项数学上界时跳过三角函数。几何常量和差分步长 `2e-6` 不变，不量化坐标，不简化模型。
- Windows 小录制在已有隔离数据工作进程中调用官方 `save_episode(parallel_encoding=False)`，省去额外编码进程的启动/退出。总工作量不超过 `200,000,000` 像素时采用该策略；较大/高分辨率录制与其他系统保留并行编码。批处理、统计、编码器及其线程数均不变。

## 相同输入的对照结果

| 项目 | 基线 | 优化后 | 解释 |
| --- | ---: | ---: | --- |
| 新 SARM，7 s 运动仿真计算耗时 | 29.1377 s | 27.4054 s | 减少 5.95%，纯计算实时系数 0.2402→0.2554 |
| 同一轮外层帧计算 P95 | 153.143 ms | 145.917 ms | 减少 4.72% |
| 同一 135 帧双相机录制收尾 | 12.4412 s | 5.9972 s | 减少 51.80% |
| 同一录制追加＋收尾总耗时 | 15.4187 s | 8.9338 s | 减少 42.06% |

仿真对照使用相同场景、初态、输入与原生步进器；240 Hz、5 子步保持原值，计时排除启动、UE、网络与录盘。新增物理状态快照在计时区域外采集。先前重复运动对照约改善 3–6%，不是数倍加速；默认旧模型两轮平均改善约 1.7%，处于运行波动范围，不宣称其整体吞吐显著提高。复杂新模型仍然达不到实时。

135 帧编码对照使用同一实际采集的原始图像和观测，不重新运行仿真。前后 `stats.json`、数据 Parquet 表、两路 MP4 文件 SHA256 和解码像素完全一致。另探索过流式编码，但没有采用，以保留原批处理统计与输出语义。

最终重启数据工作进程后的实际网页录制包含双相机各 346 帧，均为 30 Hz，收尾 13.65 s。其长度与上述 135 帧不同，不能直接用于计算 52% 的改善。60 FPS 预览下，录制前浏览器显示/解码约 51.26/59.91 FPS，录制中约 44.72/58.96 FPS；这里没有测量 RDP 客户端最终呈现帧时间。

录制期间的额外预览重绘限速并不等同于视频限速：相机流还读取共享采集画面。实际解码约 59 FPS 后，撤回了未经证明有效的预览重绘提速候选。本轮没有修改 UE 或前端生产源码。

## 正确性与运行验证

- 编译原始与新 SDF，进行 926,800 次有符号距离和有限差分梯度逐位比较，0 差异；覆盖所有模式、边界、重复调用、缓存替换、带符号零与多线程。
- 默认和新模型各 210 个 30 Hz 检查点的完整 `time_ns/qpos/qvel/qacc` 前后逐元素相同，最大差 0。这不代表检查了每个求解子步。MRP 显示转换允许浮点运算顺序造成的约 `2e-14` 量级差异，不影响权威物理状态。
- 新模型 40 s 原生稳定性与 3 次完整夹爪开合通过，400 个采样点，最大耦合误差 `4.37e-8 rad`。这不是抓取或任务盒操作成功验收。
- 服务端相关测试 72 项；适配器 111 项及 19 个子测试；采集回归 33 项；Ruff 通过。套件可能重叠，不相加冒称独立总数。没有把上轮 UE/前端测试计为本轮新跑。
- 原控制台真实接续、原生关节/键盘控制、急停/恢复、重置和停止通过；接续采集双相机各 135 帧、新模型各 80 帧、最终录制各 346 帧。独立解码视频并核对数据行数、30 Hz 样本时间及源时间单调性，完整样本无未配对相机帧。
- 窗口外迟到的旧采集包按原策略丢弃，接续与最终录制各记录 24 个 stale 包；不计入已接受的数据帧。测试 episode 的 outcome 为 failure/aborted，与 dataset complete 区分，不把录制完成冒充抓取成功。三次网页回执均无 JS 错误。

## 复现和证据

云电脑保留 `validation/platform-performance/` 下的基准、剖析、真实截图与中间失败记录。正式汇总为工作区 `delivery/platform-performance-acceptance.json`，55 张真实截图见 `validation/platform-performance/index.html`，源码和证据分别导出 bundle 与 ZIP。凭据、讲稿、运行数据与生成资产不进入源码 Git。

在服务端目录、已有云端 Python 环境中运行新增的独立 SDF 检查，输出必须使用新路径：

```powershell
& $env:SPACE_SIM_PYTHON tools/validate_sarm_20261012_platform.py --sdf-equivalence --reference-commit 9011b97c9e19939cc984f98c36085f183a27f885 --output run/sdf-check/equivalence.json
```

现有 `tools/profile_simulation_runtime.py` 同时保存 `.physics.npz`。工作区 `validation/platform-performance/verify_performance.py benchmark --reference --scene new --name <新名字>` 在独立进程中加载已保存且核验指纹的旧插件和旧 Python 方法；不加 `--reference` 对照当前实现。`writer --reference --name <新名字>` 与 `writer --name <另一新名字>` 可复用同一保留 episode；`finalize` 只复核已有产物，不重新运行仿真。

目前最大未解决瓶颈仍是新模型的精细 SDF 接触。后续若进一步优化，应继续用相同物理输入对照；降低求解频率或替换接触几何需要单独讨论，因为会改变仿真语义。
