# 六轴零位自动展开

## 行为

`teleop-zero-prepare-v2` 将场景的机械臂旋转关节初态固定为六轴零位，保存用户输入的六轴操作角度作为目标。场景启动后，前端只为本次明确的启动意图自动申请控制权并发送一次准备请求；服务端和仿真端持续用心跳授权，直到实测位置和速度稳定到位。

准备完成前不能进入遥操作，也不能开始任务采集。取消、急停、控制权撤销、页面隐藏或链路断开会撤销准备授权并制动停止；不会因重连或旧心跳自动恢复。新模式只有在实测六轴仍在零位时允许显式重试，否则应先复原场景。

## 使用步骤

1. 刷新控制网页；结束已有场景后，选择“零位启动并自动展开”（`teleop-zero-prepare-v2`）。
2. 输入 J1–J6 的操作目标角度，单位为度；数值按字面执行，不自动折返到另一圈。这里输入的是最终操作姿态，不是仿真首帧位置。
3. 点击一次“启动场景”，保持该页面在前台。系统先检查候选路径，再从六轴零位启动真实动力学运动；无需再点准备按钮。
4. 状态显示“已到位，可以操作”后，进入遥操作或开始任务采集。到位依据实测角度与速度，不是动画播放时间。
5. 中途取消或断线后不自动续走。先“一键复原初始位置”恢复场景零位，再点击“重试零位展开”；这会同时复原目标物等场景状态，不是机械臂返航路径。

目标创建后锁定；修改目标应结束场景后重新创建。超出关节限位、目标姿态碰撞或有限候选路径均不可行时，会拒绝启动并显示原因。

## 路径

场景创建时，`simulation/preparation_planner.py` 在隔离的 Python MuJoCo 进程中检查模型限位、目标物状态和机械臂相关静态接触。规划器只保存采样验证过的有限候选路点，不能声称连续动力学无碰撞证明。当前默认姿态通常采用：

```text
[0, 0, 0, 0, 0, 0]
→ [0, J2, 30, J4, 0, 0]
→ [0, J2, J3, J4, J5, 0]
→ [J1, J2, J3, J4, J5, 0]
→ [J1, J2, J3, J4, J5, J6]
```

规划器会尝试 J1/J6 不同顺序和直接路径；没有通过静态接触采样的候选就拒绝创建场景，不偷偷修改目标角度。每个采样段的单轴最大步长不超过 0.5°。计划保存模型 SHA-256，运行时模型变化会使场景启动失败并要求重新创建计划。

上图为先 J1 后 J6 的候选；相邻相同路点会去重。SHA-256 目前覆盖主 MJCF 文件，不递归覆盖引用资产。静态采样不等于任意姿态均可达，也不等于连续动态无碰撞保证。

## 模块边界

- `scene_runtime.py` 负责场景初态、目标与计划保存，以及启动进程身份；保留旧状态文件供进程清理，但不把旧实例状态返回为新启动的实例。
- `preparation_planning.py` 启动隔离规划进程；`preparation_planner.py` 仅负责限位与静态碰撞采样，避免 Python MuJoCo 和 Basilisk MuJoCo 在同一进程加载。
- `preparation_contract.py` 校验保存的计划；`arm_preparation.py` 执行轨迹、跟踪保护和实测到位判断，不直接改写物理关节状态。
- 前端负责明确的本次启动意图、授权心跳和状态展示；后端另行校验准备到位与遥测新鲜度，防止绕过页面直接开启采集。

## 执行保护

`simulation/arm_preparation.py` 只输出关节参考，不直接写物理状态。轨迹采用余弦速度过渡，并对 v2 限制关节速度和加速度。执行时根据实测跟踪误差和驱动力矩饱和动态降低共享轨迹时钟；持续受阻或饱和超过阈值则失败，不让参考继续无限累积。最终 ready 需要位置误差不超过 0.8°、速度不超过 0.02 rad/s，并持续 0.35 秒。

## 兼容性

旧的 `teleop-zero-prepare-v1` 仍表示直接以操作角度初始化；历史实例继续使用原有 J1/J6 保持语义。新场景目录和实例必须记录 `randomization_profile` 与 `arm_preparation_plan`，不能仅根据 profile 名称猜测旧实例行为。
