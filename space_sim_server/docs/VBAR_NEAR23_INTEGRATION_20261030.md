# V-bar、原夹爪双目和陀螺辅助抓取集成

更新：2026-10-30。纠正17.4 m转交旧平移程序的临时方案，改为V-bar全段负责；新增可执行的 V-bar→17.4 m调姿→原双目→平台驻留→陀螺辅助抓取入口。后续更新：本轮从110 m初始化至实际抓持的连续原生试验及独立评分通过，补充实测误差、视觉接入距离和适用范围。

## 这次实际连接了什么

`simulation/vbar_stereo_sequence.py`只协调任务阶段；同一个`VbarApproach`从入口归线、50 m、17.4 m一直生成服务星接近与驻留参考，到平台保持也不转交给旧试验的平移控制。当前选定路线采用5 cm位置、1 cm/s速度和各节点连续5 s要求，原V-bar默认参数和视觉保护策略仍保留。

17.4 m停泊完成后，V-bar暂停平移并触发目标调姿；调姿稳定后仍由同一个V-bar继续接近。没有重置动力学、导航、GNSS、关节或时钟，也没有第二套平移参考生成器。在新增显式`OriginalCameraVbarPolicy`中，5.5 m按GNSS条件停泊，1.5 m为真实视觉连续就绪检查点，随后用原五次平滑偏移路径转入作业位置。

PnP先经过曝光编码器FK坐标换算并更新导航，更新后的同一历元质心位置、速度和协方差在每个20 Hz周期传入这个V-bar。视觉接入不会使V-bar退出；平台保持后机械臂才调用抓取程序。

V-bar继续用GNSS接近，在5.5 m按导航条件停泊；约3 m开始可能取得原图PnP，视觉测量通过检查后才融合。到原近距视觉检查点（本入口为1.5 m）取得连续有效图像并停稳后，再进入视觉接近和0.5 m平台两次5 s驻留。17.4 m和5.5 m均不伪造视觉就绪。

本入口显式选择`--gnss-bridge-diagnostic`，允许健康GNSS继续越过旧12 m保护线；旧网页默认规则没有被全局删除。

## 当前相机与数据

使用`config/vision/capture26_near23_front_mount_20261029.json`，相机仍装在夹爪上；不增加长焦，不移动机位，不更改23块靶标及原环境光照。

真实左右RGB经过联合PnP，调用`Near23NavigationBridge`，使用曝光时刻的关节编码器转换为服务星本体系中的两星本体原点相对位姿，并传播图像6维协方差。该诊断入口沿用六状态`RelativeEKF`，显式采用理想合作姿态遥测转换到惯性系，额外加每轴6 mm工程不确定性先验。它不是正式运行时的24状态`PoseNavigation`已经接通的证明。

左右帧、时间戳、安装标定和FK均使用当前相机配置。无有效PnP的帧输出无效数据，不沿用旧位姿冒充新观测。滤波状态、图像测量和独立真值评分分别记录。

## 抓取怎么接

0.5 m平台连续驻留完成后，在原实际关节状态上启用已合并的`StereoPredictiveCapture`。机械臂使用当前23靶标视觉；图像暂时不可用时，沿用其有预算限制的陀螺/编码器预测，再由实际接触反馈进入闭合和力控。

共享50 Hz模拟陀螺从任务0时刻连续采样；自身运动观测器也从任务0时刻消费，不在几千秒后的抓取入口重置传感器。抓取自身的等待计时从实际激活时刻开始，照片仍保留全局任务曝光时间。平台只有一个平移控制器、机械臂只有一个伺服指令链。

验收要求实际四爪支撑、轴向保持力4.5–5.5 N连续20 s；保留10 N单接触力、20 N总爪力、2 mm压缩及服务星自碰撞保护。图像预测不能替代这些接触验收。

## 运行入口

```powershell
./scripts/run_vbar_near23.ps1 `
  -Python <已有仿真python> `
  -BasiliskRoot <匹配的原生Basilisk目录> `
  -ReferenceServer <原成功近距运行所在的server目录> `
  -ReferenceScene <保留的准备状态scene.json> `
  -Output run/vbar-near23-trial
```

脚本默认从110 m光学深度初始化，以真实400 Hz动力学、20 Hz导航/平移控制和当前原双目运行。它用隔离UE进程读取原成功运行的渲染资源与灯光，不改用户当前平台进程。历史资源目录是本次原生试验的显式输入，尚不是不依赖历史run资源的正式网页部署入口。

运行结束后`tools/diagnostics/score_vbar_near23.py`独立评分各停泊末5 s内的真值位置、速度和平台工具间隙。轨迹按20 Hz记录，每个5 s评分窗口含101个连续采样，各采样均须满足位置≤5 cm、速度≤1 cm/s；平台另要求机构中心位置和工具间隙误差≤5 cm。接触和连续抓持力在400 Hz物理步检查。任意一项失败，不能因制导已放行而判成功。结果保存在`acceptance.json`。

可另行运行`python tools/diagnostics/vbar_progress_page.py --run-directory <试验目录>`，打开该目录的`progress.html`查看阶段、采样时间和最近一组双目原图。页面每2 s刷新，读取已有记录，不改变动力学或渲染输入；最终显示独立验收结果。
