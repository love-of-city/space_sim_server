# 服务端基础 CI 提速

日期：2026-10-09

## 背景与变更

server-python 每次运行 7–10 分钟：安装依赖 2.5–4 分钟（`lerobot==0.4.4` 引入 torch 等约 1.5 GB 包，每次从零安装），串行测试约 4 分钟。近期变更集中在可视化仿真，部署脚本自 2026-09-20 后基本未变，但其测试每次占用约 40% 的测试时间。adapter-python 仅约 1 分钟，未改动。

- 测试使用 pytest-xdist 4 个 worker（windows-latest 为 4 vCPU；`-n auto` 在本地 32 进程下出现过一次偶发失败，故固定为 4）。`ci_pytest.py` 只由 gw0 写 `coverage-scope.json`；`verify_ci_guards.py` 增加探针，确认 worker 上的 skip 仍使整体失败。
- 缓存整个 venv（workspace 根的 `.venv-ci`）。key 包含 Python 补丁版本、两个仓库的 `pyproject.toml` 哈希和 ISO 周，未锁版本的依赖每周至少重新解析一次；安装后立即保存，测试失败不影响缓存。`pip check` 每次仍执行。
- `ci-exclusions.json` 新增 `deploy` 组（4 个纯 PowerShell 部署测试文件），由 `--ci-skip-group deploy` 排除。仅在 PR 未改动部署相关路径时启用并输出 notice；main 的 push 与手动运行始终全量。
- `test_video_delivery_config.py` 中 21 个部署配置校验用例改为每模块一次 pwsh 进程，用例 ID 与断言不变；渲染器参数用例去掉两个区间内部值（60、75）。

## 验证与边界

本地（Python 3.11 `.venv-ci`，32 核）：串行 190 s；`-n 4` 三次 706 passed，55–62 s；跳过 deploy 组 610 passed，38 s；全部改动后两次 704 passed，约 51 s。`--ci-skip-group` 的未知组、组文件改名（stale）均按预期报错；将 `preview_fps` 上限临时放宽到 121 时，批量后的测试准确报告 `[121]` 用例失败。CI 实际耗时与缓存命中情况记录在 PR 验证证据中，此文档不预先宣称。

`test_python_runtime.py` 在两个仓库中各测本仓库的解析脚本，不属于重复，保留。

## 风险与回退

PR 上 deploy 组被跳过时检查仍显示成功，由 main 全量运行兜底；部署脚本新增依赖文件时需同步 `ci.yml` 的路径过滤器。缓存冻结依赖解析至多一周。如需回退，通过新 PR revert，不重置或强推 main。
