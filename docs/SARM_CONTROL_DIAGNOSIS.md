# SARM 无法操控：动力学诊断与修复（2026-09-07）

## 实际加载哪个 XML

当前平台加载 `../model/SARM/platform/sarm_platform.xml`，不是编辑器中打开的
`../model/SARM/mjcf/SARM.xml`。后者是独立机械臂模型；前者是包含卫星、机械臂和自由目标的运行场景。
模型名称是 **SARM**，不是 SRAM。

## 根因及修改

### 1. 自由飞行关节错误继承了机械臂的阻尼和摩擦（主要失控原因）

平台 XML 的默认关节参数为 `damping="0.5" frictionloss="0.05"`。
`cubesat_free` 和 `capture_target_free` 原来仅指定 `type="free"`，也继承了这些参数。
独立 MuJoCo 3.7.0 编译检查确认：两个自由关节的六个自由度均存在这些被动参数。

轨道速度约 7612.6 m/s 时，仅卫星平动阻尼力的模就达到 **3806.3 N**。
这种非物理外力使未收到运动指令的机械臂快速偏离初始姿态，原有受限 PID 力矩无法保持姿态。
不是 UE 没有绑定关节，也不是前端指令没有抵达：对照记录中 action sequence 更新、
`command_stale=false`、IK 参考值正常改变，但实际关节已在无输入时失控。

修复：在这两个自由关节上明确设置
`damping="0" frictionloss="0" stiffness="0" armature="0"`。
保留正常机械臂关节的阻尼、摩擦、接触设置和原有执行器限幅。
修改后编译模型的自由关节被动参数及上述平动阻尼力均为零。

### 2. 重力模块早于正向运动学执行

`simulation/teleop_grasp_unreal.py` 原来将重力放在动态任务优先级 19000；
当前原生 MJScene 的正向运动学优先级是 10000，而较大的优先级先执行。
因此重力读取尚未更新的刚体状态，导致启动时出现 `Nan, Inf or huge value in CTRL`。

重力优先级改为 **9500**：星历 20000 → 正向运动学 10000 → 重力 9500 →
轨迹/控制器 9000 及以下。修复没有关闭地球/太阳重力，也没有引入 Python 逐步状态转发。
单独修正执行顺序可消除 CTRL 警告，但不能解决上述自由关节阻尼造成的失控。

### 3. 自由目标的速度混用了局部和惯性参考系

原代码给卫星赋轨道速度，却只给目标赋局部小速度，导致目标以约一个轨道速度相对卫星漂离。
之前“第二个刚体不能赋轨道速度”的规避注释掩盖了自由关节被动阻力问题。

现在目标速度为 `orbital_velocity + target_linear_velocity_m_s`，与卫星处于相同惯性参考系。
修复自由关节和任务顺序后，两者同时具有轨道速度可正常运行。

### 4. 夹爪沿用过小的位置增益

双指为米制滑动关节。原 Kp=0.2 N/m，在完整 0.0375 m 行程内最大比例输出仅
0.0075 N，小于 XML 中 0.01 N 的摩擦损失。

`../model/SARM/platform/scenarios/scenario_sarm_grasp.py` 中只将最后两项 Kp 改为
**40 N/m**。保留原来的 **0.05 N/指限幅**、Kd、关节阻尼和摩擦，未提高安全力上限。
原生对照测试已确认可以按毫米级指令打开并关闭。

### 5. 旧模型残留

- 第 5 轴控制限位改为 ±3.1416 rad，与 XML 一致；第 6 轴仍为 ±6.2832 rad。
- 前端夹爪速度改读下标 6 的滑动关节，而非下标 5 的旋转关节。
- 雅可比秩的总维数改为 6。历史协议字段 `joint_velocity_rad_s` 的末两项实际为 m/s，
  此次未破坏既有协议命名或兼容字段。
- 运动学、遥操作与安全测试的旧 SO101 模型/五轴/角度夹爪样例已迁移到 SARM。
  超时测试改用可控时钟，避免 Windows 短时 sleep 与时钟分辨率造成的随机失败；
  此次没有修改生产安全控制算法。

## 验证结果

原生测试使用私有控制端口 18767、渲染端口 16559，不连接正在运行的后端或 UE，
沿用现场场景的目标参数并将机械臂初始化为标准 PREGRASP。
正式文件经过 5 秒基础测试及 14 秒扩展测试，扩展测试得到 420 个观测包、421 个渲染帧，
正常退出，无 CTRL/NaN 警告，所有关节状态有限。

## 使用与验证边界

前端已构建。本轮没有启动或接管用户的 UE 场景，检查时现场场景处于 stopped。
刷新前端，再启动场景即可加载新模型参数及仿真脚本；已有仿真进程不会热加载修改。
本轮不涉及 UE C++ 变更，因此不需要再编译 UE 或重新导入网格。

这是原生动力学和控制协议测试，不是本轮浏览器键盘 → 后端 → UE 画面的端到端验收，
也不代表已验证长时间运行或所有抓取碰撞姿态。
标准 PREGRASP 的腕部处于近奇异姿态，雅可比显示 5/6 属于正常运动学限制；
阻尼 IK 会投影无法实现的末端速度，某些方向可能响应较弱，不应再用旧的 /5 显示掩盖这一点。
原有目标初始角速度归零的兼容逻辑本轮未改变，非零目标自旋需单独验证。
