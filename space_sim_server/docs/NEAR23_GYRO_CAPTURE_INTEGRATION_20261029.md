# 23块靶标双目与陀螺预测抓取整合

更新：2026-10-29。基于统一仓库 main `5067bde`（包含刘丹旭的 PR #35），工作分支 `feature/near23-gyro-capture-integration-20261029`。本次范围为末端抓取，未修改 V-bar 接近和远距导航规则。

## 合并后如何工作

1. 相机随抓夹运动，左右眼在同一采样时刻各拍一张原图。图像进程识别23块多尺寸方形 ArUco 靶标；用已知角点、双目内参和安装关系联合求解目标位姿。
2. 用目标本体系下的机构参考点 `[0.1755, 0.05475, 0.0420787001299893] m`，经过目标到左相机的 `R、t` 和相机到抓夹的固定安装关系，得到机构中心在抓夹中的位置和接口朝向。不能直接使用 `tvec` 作为抓取距离。
3. 将这次结果与**拍照时刻**的关节编码器/FK及自身运动估计对应，变换到共同参考系。图像到达后再动过的机械臂，不会被误当成目标运动。
4. 图像有效时持续更新；短时没有合格图像时，沿用最后的目标参考位姿，结合服务星共享的50 Hz模拟陀螺、两臂编码器及装配质量模型，估计当前抓夹与机构的关系。陀螺测的是角速度，位置补偿还依赖编码器和质量模型。
5. 靶标重新出现时，重新校验图像质量和位姿跳变，再恢复视觉修正。接触后沿用原来的闭爪、建立约5 N轴向支撑力和保持流程。已有过载、提前碰撞、陀螺异常等保护继续生效。

这将用户的小靶标持续观测与同学的自身运动补偿接在同一控制流程中。不会按“到0.12 m就盲抓”强制切换；是否使用视觉取决于当帧图像质量。

## 固定配置及质量条件

- 23块 `DICT_4X4_50` 方形靶标，ID 0–22；黑框边长50、20、10、6、4.5 mm。仍为零厚度显示贴膜，未增加碰撞几何或质量。
- 双目中心对齐同学腕部相机位置：左眼 `[0.075, 0.060, 0.031] m`，右眼 `[0.075, -0.060, 0.031] m`，父体 `teleop/gripper`；光轴沿抓夹−Z。
- 每眼1920×1920，水平/垂直视场100°，基线0.12 m，10 Hz，零畸变；未新增长焦相机。
- 左右眼各至少一块完整有效靶标，可以是不同编号。最短黑框边≥12 px；每眼重投影RMS≤2.5 px，最大单角点误差≤5 px，正深度，歧义候选拒收。
- 数据包含会话、原图帧号、曝光仿真时间、配置指纹和双眼质量。过期曝光、场景不符、配置不符和单眼不合格不会作为新的视觉修正。抓取输入不读取渲染外参或目标真值。
- 仿真保留原环境、太阳/地球、材质及原生工作灯参数。测试工具使用私有渲染端口和独立 streamer，不连接现有网页控制端口。

## 代码入口

| 层 | 文件 | 作用 |
| --- | --- | --- |
| 双目图像 | `backend/space_arm_platform/multicamera_pose.py` | 保留用户的联合重投影算法，输出双眼质量指标 |
| 独立图像进程 | `backend/space_arm_platform/vision_worker.py` | 配置选择联合双目或原有算法 |
| 接口换算 | `backend/space_arm_platform/stereo_capture_packet.py` | 静态标定换算机构位置/朝向，原子发布 |
| 抓取输入 | `simulation/stereo_predictive_capture.py` | 检查会话、曝光时间、配置和双眼质量 |
| 预测/接触/力控 | `simulation/visual_predictive_capture.py`、`simulation/components/capture26.py` | 复用同学原控制器，增加双目输入选择并保留重置配置 |
| 场景 | `simulation/near23_capture.py` | 同时选择新机位、23靶标和陀螺预测控制，避免只改其中一处 |

原有腕部单目模式仍为默认。新的场景必须明确启用 `input_source=near23_stereo`、`mode=predictive_grasp`、`held_target_pose=true` 以及相同的双目标定文件。

从已有保存场景生成一个新场景（不覆盖原文件）：

```powershell
python tools/enable_near23_gyro_capture.py --scene <原场景.json> --output <新场景.json> --evidence run/near23_trial
```

用团队兼容的 Basilisk/MuJoCo 原生环境运行；普通 Python MuJoCo 不能替代。`tools/run_near23_gyro_trial.py --help` 给出本机独立图像闭环试验参数，`tools/score_near23_gyro_trial.py <运行目录>` 从独立真值记录计算结果。运行目录和原图不提交 Git。

## 验证记录

首段8 s实际试验（新机位、原模型/原灯光）：79组双目全部有效，机构中心三维位置误差RMSE **0.318680 mm**、最大 **0.538160 mm**，姿态误差RMSE **0.122632°**、最大 **0.245531°**。这是接口和机构准备段结果，不能作为已经抓持成功的证据。

完整接近、力控保持，以及短暂丢视觉后的恢复结果，待运行完成后在此补充。图像逐帧按会话/帧号/曝光时间与独立真值配对，分别统计图像误差、视觉接近/盲行预测误差、接触峰值、支撑爪数和连续保持时间。

## 适用范围

- 当前预测器假设接触前目标在共同轨道参考系内保持，利用服务星装配质心近似守恒补偿机械臂反作用。任意平移推力、目标翻滚、碰撞后的目标自由运动不在该近似适用范围内。
- 初始1.5 s保持机构静止，估计共同轨道角速度与偏置合量。这不是可独立观测的真实陀螺零偏标定。
- 本次沿用同学的诊断运动/时间预算（最多90 s无新视觉、180 mm盲行等），它们是停止条件，**不能解释为在整个预算内精度都得到保证**。实际丢视觉验收只以具体运行的误差和时长为准。
- 平台原有飞轮姿态控制的真实姿态反馈范围未在此重写。本次新增误差进入抓取侧自身运动补偿，不等于完成了整星惯性姿态导航系统。
- 实际试验用锁步图像：收到该帧实际UE图像后才继续物理积分。能验证图像闭环和接触动力学，不能证明实时10 Hz吞吐、真实图像延迟、实物精度或多工况鲁棒性。
