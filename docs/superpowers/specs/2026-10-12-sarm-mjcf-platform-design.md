# 新版 SARM MJCF 平台动力学接入设计

日期：2026-10-12
状态：待用户审阅；本文件不是接入完成记录。

## 目标与已确认范围

用户要求完整采用 SARM_mjcf_20261012/SARM_convex.xml，并在现有网页平台查看和操控。机械臂、四连杆抓夹、任务盒、质量、惯量、关节、碰撞与螺纹定义均以交付文件为来源。保留平台在轨环境、反作用轮功能、UE 隔热膜显示。静态关卡和单独 MuJoCo viewer 均不能作为完成证据。

## 当前检查所得事实

- 当前 run/scene_runtime.json 最近实例是 sarm-task-box-free-plugs，当前完整模型尚未进入模板目录。
- teleop_grasp_unreal.py 的 SARM_JOINT_NAMES、CartesianTeleopTarget 和遥测使用六个机械臂转轴及两个米制滑动手指。
- scenario_sarm_grasp.py 的 JOINTS、ACTUATORS、初始化与控制图依赖 finger1/finger2、cubesat_bus 和 capture_target。
- 新抓夹有六个转动关节，两个 connect 闭环约束、一个反向耦合约束和一个 tendon 位置驱动。
- 新模型为固定基座，抽屉滑轨挂在 worldbody；当前平台为在轨自由基座，不能直接替换 XML 路径。
- local_mujoco_stepper.cpp 从 Basilisk 已加载的 mujoco.dll 解析函数并检查头文件版本。不能先导入 Python MuJoCo 的另一个运行库。
- 随包 .so 是 Linux 编译产物。Windows 测试 DLL 已成功加载到独立 MuJoCo 3.7.0，但未验证平台运行库插件注册。
- 独立测试中的插头 QACC 不稳定仍未定位；螺纹完整旋拧和机械臂实际抓持没有验收通过。

## 模型组织与场景身份

保留 model/SARM_mjcf_20261012 原始输入及导入清单，不覆盖交付文件。新增可重复运行的装配生成器，生成平台用派生 MJCF 及来源清单。场景模板新增 sarm-task-box-20261012，并在界面标注实验状态；旧模板用于回归与旧数据复现。

生成器将原始 base_link 装配置于平台自由基座坐标系，显式映射平台名 cubesat_bus；关节和几何原名尽量保留。原始基座惯量作为主体参数来源，反作用轮作为平台附加部件单独记录，检查没有重复质量。保留完整新版机械臂和任务盒，不混入旧任务盒碰撞或旧手指。

抽屉滑轨及其子卡扣绑定到主体基座，保持源模型零位的世界装配姿态；原有三个自由插头、螺栓及紧固件继续为自由刚体，继承初始共同在轨速度。既有捕获目标若作为平台附加场景物体保留，必须单独标识，不能冒充新任务盒组成。

工具中心从 ee_site 映射到平台运动学接口，腕部相机与总览相机显式配置。生成器记录全部重命名、坐标变换和平台附加项。

## 插件加载

将螺纹源代码纳入可复现 Windows 构建入口，产物置于本地 run/native_acceleration。构建采用平台运行库匹配的头文件及导入符号，不提交 DLL。记录源码哈希和运行库版本。

在任何新版模型加载之前，向 Basilisk 的同一个 MuJoCo 运行库注册插件；模型发布副本和本地积分副本都使用同一注册表。独立验证子进程也必须先注册插件。缺失插件、版本不匹配和注册失败应阻止该模板启动，并返回明确诊断，禁止删除 SDF 几何后静默降级。

## 控制与状态接口

保留六轴笛卡尔 IK、deadman、急停和限位控制。添加按模型描述选择的抓夹适配器：旧模板维持双滑动手指；新模板通过单个 tendon 驱动真实四连杆，保留被动关节及闭环约束，不用两个虚拟滑块替代。

新版驱动保留源 kp/kv、限幅和传动参数，逐项验证平台接口的单位与符号。网页原张开/闭合输入映射为驱动参考增量，夹爪状态应标注驱动角或归一化开度，不能把角度写入 gripper_position_m。归一化开度须根据实测指间距离标定，初期可直接报告驱动角与指间距离而不声称已标定。

动作和观测携带模型版本及抓夹类型；新增字段维持旧模板兼容。采集元数据记录关节名、单位、驱动参考、模型哈希及运行库版本，禁止混淆新旧动作语义。暂停、失联和急停必须清除运动输入并保持受控状态。

## 时钟、初始化与稳定性

保留平台 240 Hz 调度及 30 Hz 视频/采集时钟。新版源步长为 1 ms，使用适当数量本地子步，使每子步不大于 1 ms，并记录实际值；闭环动力学不使用旧滑动爪的默认配置冒充源参数。

初始化写入全部自由体与闭环关节状态，先做约束残差检查，再启动积分。自动展开路径需要针对新版工具几何重新验证，因此新版首次接入使用显式操作姿态直接启动，禁用未经验证的旧自动展开路线。

QACC/NaN、仿真时间异常回退或超限状态触发失败与停止，禁止把 MuJoCo 自动重置后的零位显示成恢复成功。稳定性问题先保存复现记录；任何对交付碰撞、惯量、阻尼的修复须独立列明前后值及依据。

## UE 与平台生命周期

实时帧由新模型的刚体/几何状态生成。导入可见网格，透明碰撞分片不在画面重复显示。隔热膜作为可视附加层绑定新版基座，并验证比例、镜像和装配位置。

由平台场景管理器启动、停止和重置新版实例，沿用受管 UE/信令/仿真进程；关闭临时静态预览进程后启动真正场景，避免重复 streamer。平台状态显示实际物理连接状态和运行时间，不制造遥测来清除“未连接”。

## 验收与完成边界

1. 来源与结构：哈希一致、所有引用存在、闭环/tendon/SDF 数量保留；新旧模板均可解析。
2. 原生加载：平台实际 Basilisk/MuJoCo DLL 下，发布和积分模型均成功加载；版本不匹配有明确失败。
3. 动力学：至少 10 秒静置有限值、无重置、闭环误差有界；抓夹开合循环、三个插头扰动、抽屉/卡扣和螺纹分别报告结果。
4. 控制：网页六轴动作及夹爪动作驱动真实新模型，deadman/急停有效，读取实际状态而不是只检查目标值。
5. 生命周期：在网页选择新版模板并启动，重置恢复全部活动件，停止清理本实例进程。
6. 采集：完成短 episode，视频与观测对应同一新版模型、时间单调、动作单位明确。
7. 展示：网页实测有视频帧、模型版本和物理时间，截图保留；实际抓取/插拔/旋拧成功与基础接口通过分开报告。

达到 1–6 才称“平台基础接入完成”。插拔、旋拧未通过时标注实验限制；若静置或小幅操作即失稳，不将该模板设为稳定默认场景。
