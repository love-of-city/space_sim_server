# UE 网页串流退出排查记录（2026-09-11）

## 已确认的现象

11:55:06（本机时间）的 UE 崩溃报告位于适配器项目 `Saved/Crashes/`：

- `EXCEPTION_ACCESS_VIOLATION reading address 0x0000000000000124`。
- 异常线程的调用栈落在 `UnrealEditor-PixelStreaming2RTC`，不是模型 XML 解析或 Python 仿真调用栈。
- 出错前同一个播放器先加入、紧接着离开；UE 随后才处理加入回调，报告 `Unable to find participant`。
- UE 已不在进程列表，但 `run/scene_runtime.json` 仍为 `running`，仿真及其 Conda/Python 子进程仍存活。

不能仅凭这些信息把问题归因于远程桌面、GPU 驱动或公网 IP。本次没有修改模型、仿真动力学代码、UE 引擎安装文件或适配器源码。

## 项目侧修复

1. `frontend/app.js`：场景从启动切换到 running 时，保留已经等待/握手中的播放器；不再无条件重新建立连接。原来的绝对 10 秒重连改为 60 秒停滞检查，串流发现及 RTC 协商进展重置检查，成功连接取消计时。
2. `signalling/server.mjs`：对同一串流的重复订阅幂等；不再发送同一参与者紧邻的断开/加入对。未订阅或已离开的播放器不能由迟到的 ICE/SDP 自动挂到任意相机；旧串流消息不能送到已经切换相机的播放器。
3. `signalling/peer_departure.mjs`：浏览器离开时立即撤销信令路由；UE 侧参与者清理等待 offer 确认协商已开始，并留出 500 ms 回调消退时间。没有 offer 的异常情况最多等待 10 秒，UE 连接退出立即释放全部记录，防止无限占用。延迟仅针对 RTC 资源释放，不延迟后端操作链路的断连保护。
4. `scripts/scene_process_helpers.ps1`：同时监控渲染器和仿真，UE 异常退出即标记失败并清理整棵仿真进程树；清理核对 PID/启动时间。手动停止先写入停止状态，避免误报成崩溃。

这是针对已识别触发时序的项目侧防护，不是修改 EpicRtc 内部代码，不能声称修复了所有引擎崩溃。
