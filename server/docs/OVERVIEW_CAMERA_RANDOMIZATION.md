# 全局相机随机初始化

完整 `sarm-task-box-20261012` / `sarm-task-box-20261012-sdf` 操作台支持 5 个离散机位。
新场景或每次自动采集尝试开始时，从中等概率选择一个；运行期间及一键复原均重放已保存的机位。
它固定在卫星本体坐标系，随卫星一起运动，不跟踪某个随机摆放的操作件。

新建场景及采集尝试只使用下述 5 个固定机位，`overview_camera_sampling` 为 `"presets"`。
即使源场景保存了旧的 `"continuous"` 偏好，新采集尝试也选择固定机位。
历史 v5 连续位姿仅保留加载、复原与记录验算，不再用于新采样。
需 `randomize_overview_camera: true` 才启用机位随机选择。

## 网页与命令行

- 场景实例：勾选“全局相机随机初始化（5 个固定机位）”，再创建场景。旧实例及未勾选时沿用原相机。
- 自动采集：同名开关默认勾选。每次尝试根据本次 seed 重新选择，允许相邻尝试选中同一机位。
- 统一批量采集脚本：`collect_scripted_tasks.py`
  增加 `--randomize-overview-camera`；`--no-randomize-overview-camera` 显式关闭；不传时继承源场景。
  采样方式默认 `presets`，即使源场景使用连续采样，新批次也从 5 个固定机位选择。
  `--overview-camera-sampling` 只接受 `presets`。
- 并行采集：`collection.json` 的 `randomize_overview_camera` 控制，随仓库提供的配置为 `true`。
  `overview_camera_sampling` 固定使用 `"presets"`，逐 worker 显式传递。
  仓库配置明确设为 `"presets"`；网页自动采集同样固定使用这 5 个候选机位。
- API：`POST /api/scenes/start`、`/api/scenes/instances`、`/api/collections`
  接受严格布尔字段 `randomize_overview_camera`；为兼容旧客户端，省略时为 `false`。

这些机位按当前完整任务盒标定；其它模板和锁紧件局部特写 demo 不接受此开关。
网页/后端更新后需重新构建前端并重启对应服务，新建场景或批次生效；已运行实例不切换。
随机机位本身复用既有渲染相机协议。相机补光涉及 UE Runtime 更新，需重新编译运行时后再创建场景；
构建方法见服务端 README 的“拉取代码后的 UE 运行时构建”。

## 全局相机补光

全局相机配有沿镜头方向照射的白色聚光灯，使用与腕部灯相同的渲染路径。
灯挂在最终的全局相机上，随固定机位选择、卫星运动及相机父体变化更新，
预览和权威录制共用同一个世界光源，不依赖太阳是否照到操作台。

灯的照射范围为 2 m，外锥半角为 89°，覆盖当前 v7 的 85° 及历史 v6 的 95–105° 正方形视野角点；工作体积八角点均在灯的内锥内。关闭灯自身投影，
避免机械臂遮挡补光。初始强度为现有适配器单位的 8000，使用白光与低镜面反射比例。
参数定义于 `simulation/camera_lighting.py`，不改变太阳光、轨道相位或已保存的相机位姿。
相机从当前 manifest 移除时，其灯隐藏；恢复相机后重新挂接，避免从旧机位继续照射。

离线采集在正式录制前，使用保持不动的初始姿态以 10 Hz 实际渲染两路相机，
使默认 5 秒预热能够准备材质和渲染管线，避免首帧出现临时棋盘材质。
预热不产生数据集图片或网络输出；正式录制开始后停止该额外渲染，按权威帧采集。

补光路径的历史 v4 真实 GPU 验收在无太阳光、固定曝光下逐一检查 P0～P4 的开灯/关灯对照，
并检查切换机位、返回 P0、腕部灯及日照情况。机位标定更新后应按当前位姿重新检查实际图像，
历史补光证据见根归档
`archive/2026_10_26_全局相机固定机位与背光补光.md`。

2026-10-26 的 v6 历史验收按该组机位完成五组无太阳光的原始 RGB 开关灯对照、返回 P0、腕部灯控制和
P0 日照检查，并成功试采一条抽屉任务：1813 帧、两路共 3626 张图像。
全帧解码、来源匹配和实际相机外参检查通过；首帧及中末帧经官方 LeRobot 读取并检查。
完整证据及机位对照见根归档

## 记录与验收

新建预设模式场景使用 `space-arm-overview-camera/7` 和独立随机流
`space-arm-overview-camera-presets-v7`，相同版本和 seed 可复现，
不同版本不保证同一 seed 选择相同的机位 ID。相机采样不移动关节、布局、轨道、噪声和光照的抽样流。
场景及 episode 元数据的 `scene_instance.overview_camera` 保存版本、机位 ID、选择 seed、
本体位置、安装点、安装高度、协议朝向、视野和参考中心。自动采集 attempt summary 另存 `overview_camera`，
`collection_config.overview_camera_randomization` 保存同一份记录。

历史连续记录使用 `space-arm-overview-camera/5`、独立随机流
`space-arm-overview-camera-continuous-v5` 和分布标识 `uniform_continuous_rejection`。
记录不含预设 ID；它保存选择 seed、实际位置与朝向，以及安装中心候选范围、实体安装面范围、
基座最小距离、包络视锥范围、边缘余量和拒绝采样次数。加载时重新根据已保存版本和 seed
验算完整记录，任何被改写的约束或位姿都不能通过校验。采样只使用本相机的独立 RNG，
不改变机械臂关节、布局或轨道的随机流。

录制加载时校验配置与 seed/版本相符，不在加载、重置和逐帧渲染时重新抽样。
自动采集验收还逐帧核对 UE 回传的实际全局相机外参与同帧卫星姿态、保存的机位相符，
避免只改了元数据、渲染仍使用旧机位的记录进入成功集合。
机位随机化与操作台布局池可组合；几何视野覆盖不代表所有动作过程都无遮挡，正式批采集仍需检查视频。
历史 v1（台面上方 50–72 cm）、v2、v3 和 v4 的场景、数据仍按保存的版本及抽样流校验、重放，
其中 v4 使用 `space-arm-overview-camera/4` 和 `space-arm-overview-camera-presets-v4`。
加载和重置不会改写历史记录；下一次采集尝试一律采用固定 v7 机位。
v2 的视野和外参检查遗漏实体安装条件，存在机位垂直投影超出本体的问题，已被 v3 修正。
未开启随机化的场景仍使用模型自带相机。

历史 v1 的真实短录制验收见根目录 `archive/2026_10_24_全局相机固定机位随机初始化.md`；
v2 的历史实拍见 `archive/2026_10_24_全局相机30cm机位调整.md`，
v3 的安装点修正见 `archive/2026_10_24_全局相机实体安装约束修正.md`，
v4 的 P3 重定位与实拍见 `archive/2026_10_24_P3机位远离机械臂基座.md`。
当前不自动按遮挡情况过滤机位。
