# SpaceSim 卫星自动驾驶 Benchmark：最终交付目标

状态：实施中。用户于 2026-11-06 授权持续完成最终成品。本文件定义交付合同，不是已实现能力说明；实际可运行能力和验收结果由任务注册、运行证据及 PR 分别报告。

完成并交付可供团队实际使用的 SpaceSim“卫星自动驾驶 Benchmark v1.0”。最终产品包括完整任务库、真实仿真场景、方法接入接口、独立评分、批量评测、基线结果、原工作台集成、复现说明和配套PR。持续实施至最终交付验收完成；需求分析、第一轮样例、目录、单元测试或演示不构成完成。

【范围与依据】
1. 以用户提供的老师最终版122项为来源：S01–S26、D01–D62、M01–M24、T01–T10。建立稳定内部ID、版本及来源映射，解决前后两版编号变化与子技能/变体/端到端混列。共享能力用任务族和参数变体实现。
2. 覆盖姿轨控、导航、安全、发现/感知、远近距交会、保持/伴飞、V-bar/R-bar、绕飞检查、合作对接、非合作稳定/旋转/翻滚目标抓取、多星编队/感知/接近/抓取、异常恢复与端到端任务。终点为可靠对接/抓取连接确认，仅保留确认所需短时保持；不扩展至捕获后的组合体控制、拖曳、维修、加注、装配或释放。
3. 每项都有机器可读规范、实际执行映射、独立评分及至少一个符合语义的可运行配置。P0–P3决定建设顺序，不自动削减最终范围。unsupported、skip、空实现、预录图像、逻辑捕获或占位评分不算交付；外部缺口持续记录并解决，未经用户明确变更不能据此宣告完成。交付有限、冻结的场景矩阵，不承诺无限参数组合或所有实物硬件。
4. 单/双/多星、受控主体数、合作程度、集中/分布式控制分别声明；视觉必要性与传感器组合分别建模并兼容V0–V3。区分真值状态、模拟传感器、真实图像闭环。产品评价不同方法，不要求训练出所有场景的最强模型。

【项目基础和约束】
5. 开发入口D:/SpaceRendezvous/space_sim_unified。从最新main建隔离工作树；服务端和UE适配器配套变更同分支、同PR。初查本地98449ee，已取得2026-11-05主线d47b669，包含PR41/45的near23_vbar_v1正式导航/抓持接续与恢复修复。按最新源码核验，不把旧文档当现状，也不把历史单种子检查点续跑当本次全程批量验收。
6. 复用Basilisk在轨模型、LocalMujocoStepper、原生伺服/接触、团队SARM/capture26与目标星资产、GNSS/陀螺/时延历史、Near23图像导航桥、V-bar、实际抓持、MissionRuntime、独立审计、数据采集/回放及策略接口。补齐卫星平移/姿态/多主体动作契约；现有机械臂7维接口不能冒充驾驶接口。
7. 复用原工作台、自动采集、数据集和用户页面，不另建平行平台。保留已有遥操作、交会、数采、策略控制、取消/恢复和数据回读能力。

【必须交付的成品】
A. 完整任务规范与目录：122项来源映射、任务族、优先级、参与主体、合作/传感器、初态分布、目标、观测白名单、动作、单位/坐标/参考点/时间、动力学/资产版本、安全/成功/失败/超时、评分、难度/扰动、数据划分、执行入口。提供版本化schema、严格校验与兼容规则。
B. 环境与方法接口：统一reset/step/close和现有平台适配，明确控制权；支持传统导航/制导/控制器、脚本基线、外部Agent/VLA。感知任务评价估计输出，闭环任务的动作实际改变物理状态及后续图像。
C. 全部任务族场景：实现姿轨控、交会、保持、绕飞、撤离、对接、非合作抓取、多星协同与端到端流程；补齐声明的相机/深度/测距等传感器和资源/故障模型。视觉任务用真实渲染，非合作任务禁用目标合作遥测；带标志物合作路线不能改名冒充无标志非合作。必要新资产有明确来源、身份、许可和保真度，不伪称团队模型。
D. 独立评分与结果：从权威物理/观测日志计算，不能信任控制器success或阶段名。输出成功率、阶段完成、耗时、控制/视觉误差、安全裕度、燃耗/能耗等适用资源、失锁/恢复、通信与扩展性。未建有效模型的指标不得伪造。安全硬约束违反否决成功，区分计划接触与碰撞；策略失败、基础设施故障、无效初始化、取消单列，不丢失败样本。
E. 批量评测CLI/API：列举/校验任务、能力检查、单例/整套运行、取消、恢复、重评分、汇总导出。绑定随机种子、Git/任务/资产/相机标定版本及真实动作回执；冻结训练/调参/测试划分；失败重试不能择优或改变分母；隔离进程、端口、目录，避免跨回合残留。
F. 基线与对比：复用现有传统方法，提供可替换策略示例及无动作/故意违规负对照，必要oracle仅独立诊断分轨。每个任务族有真实运行、正负判据校验和基线适用范围；方法在困难场景失败不等于Benchmark不合格，脚本成功不称模型能力。
G. 用户入口和研究交付：原页面选择任务、参数、方法、运行并查看结果；可导出研究结果；安装、配置、方法接入、批评测、复算、排错说明与自动生成的能力矩阵。代码、必要配置及许可资产通过个人分支/PR交付；最终结果摘要、证据索引和复现所需数据可追溯，运行数据不入源码Git，不堆积重复报告包。

【正确性底线】
10. 真值只供环境/独立评分，策略只见声明观测；测量、后验、控制参考、请求动作、实际动作与证据分开。视觉不得由真值位姿代替；连接不得用距离阈值、瞬移、未经物理支持的焊接替代。
11. SI、J2000/LVLH/TNR/本体/相机/TCP、四元数顺序、COM/原点/杆臂显式声明。GNSS不能声称提供姿态。曝光/采样/投递/处理时间、仿真时钟与墙钟分开。
12. reset恢复物理、导航、传感器随机流/在途包、关节/飞轮、策略会话；阶段接续保持连续状态。合法初始化之外不能改qpos/速度或重置误差。驻留/抓持由连续有效采样累计，重复/丢帧/回拨不能增加证据。故障在实际观测/执行/通信层生效，并报告是否触发。
13. 能热、柔性捕获、复杂多星、未知几何等缺口须有明确工程模型与验证；误差/假设可见，不降低积分精度、取消安全约束或使用替身来获得假通过。

【验收与完成条件】
14. 先核验最新源码、云端环境/资产/进程及现有成功路线，冻结需求映射和验收矩阵，随即实施规范/评分/runner和各任务族。阶段成果持续提交审查，不能代替最终交付。
15. 每个任务族至少3个独立固定种子；核心P0及代表性端到端任务至少10个冻结测试种子，报告样本数/不确定性/全部失败。含边界与异常，验证真值泄漏、安全否决、视觉失效、接触假阳性、复位/交接及离线重算。矩阵不能为全绿删失败。
16. 完成相关后端、前端、适配器和根CI required checks；受影响UE/原生重建并核对加载指纹。实测原生动作、真实图像闭环、物理抓持、录制回读、网页启停/取消/重置、批评测和导出；mock、短连接、基础测试不能替代。
17. 至少一次正式入口远距起步至真实抓取终点的不中断全程，独立核验连续性/图像/停泊/接触。合作、非合作、多星各有与声明一致的运行结果；旧结果和本次结果分开。
18. 修复兼容及审查问题；提交源码、配置、可复现说明与结果，推送个人分支并创建/维护PR。不代团队合并main；共享线上切换以明确授权为界，先在本人隔离环境完成成品。
19. 仅当完整目录可追溯、全部承诺任务可执行可评分、无空实现/伪通过、团队能接入方法重跑、核心路线原生/UE/网页验收完成、真实基线及失败边界清楚、检查通过、最终交付和PR齐备时标记Goal complete。否则继续推进并如实报告剩余工作，不以时间、难度或已有框架为完成理由。
