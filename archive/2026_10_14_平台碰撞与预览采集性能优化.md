# 平台碰撞、预览与采集性能优化

本分支基于 main `662d829`，集中移植此前个人分支的通用平台性能改进，并增加 SARM 导向孔的保守碰撞排除。远程交会功能没有作为依赖合入。

## 变更与保持的行为

- 新版 SARM 的螺纹杆完全处于导向孔内时，先证明外包圆柱与孔壁不相交，避免对确定无接触的杆/导向孔运行通用 SDF 搜索。检查整段杆轴的两个端点，加入杆最大半径、接触 margin 和浮点误差余量；倾斜、偏心或接近边界时回退原算法。只识别本插件 mode 2/4，其余碰撞对仍调用原函数。
- MuJoCo 的显式 pair 不经过 contactfilter，因此在注册本插件时通过公开 `mjCOLLISIONFUNC` 表包装 SDF/SDF 检测器。保持原检测器并逐对委托；不修改模型、碰撞矩阵、接触参数、SDF 采样数、积分步长、求解精度或距离/梯度算法。插件与现有加载器一样在进程内保持加载。
- BSK 引力仍按相同顺序调用原生逐刚体求值，只合并返回数组的转换；单位坐标轴 MRP 转换省去中间旋转矩阵。
- UE 预览使用连续播放时钟、有限缓冲与倍速感知的有界外推；权威采集使用原时间戳及状态。前端默认最高不超过 60 FPS，保留用户选择更高帧率的能力。
- Windows 小录制使用官方 LeRobot 原进程批处理编码，保留图像、统计和编码语义。另移植保存前将 shape-(1,) 标量转为零维值的 NumPy 2 兼容修复；大录制保留并行编码。

圆柱包含判据的依据：螺纹杆的所有点都位于半径 12 mm、局部 z∈[-110,0] mm 的圆柱内。正交投影不增加截面圆盘半径；轴段径向距离的最大值由两端点给出。若该上界加保守余量小于导向孔半径 12.65 mm，两者的非正 SDF 区域不相交。检查每次使用当前姿态，无跨步姿态近似或缓存接触。

参考：[MuJoCo 3.7.0 碰撞分派与显式 pair 过滤](https://github.com/google-deepmind/mujoco/blob/3.7.0/src/engine/engine_collision_driver.c)、[SDF 接触生成](https://github.com/google-deepmind/mujoco/blob/3.7.0/src/engine/engine_collision_sdf.c)。

## 验证进度

当前已完成的开发验证：2880 组原生碰撞比较，覆盖偏心、倾斜、轴向偏移、margin、反向 geom 顺序、轨道量级坐标及其他模式回退；原检测器产生 17070 个接触，完整接触结果零差异。7 s 新 SARM 六轴运动的 210 个物理采样点，时间、qpos、qvel、qacc 与此前已优化基线逐元素完全一致。

第一轮纯计算耗时从此前优化基线的 29.07 s 降至 24.26 s；正在执行 main 与候选的交替重复测量和完整回归。此单次结果不作为最终收益承诺。复杂模型尚未达到实时。

逐点精确缓存候选没有稳定提速，未采用。解析梯度候选即使单点梯度差异小于 1.6e-7，完整运动轨迹仍有明显偏差，已撤回；最终继续使用原 2e-6 中心差分，未放宽等价判据。

复现（在服务端目录，使用匹配 Basilisk MuJoCo 3.7.0 的已有 Python，输出选择新路径）：

```powershell
python tools/build_sarm_plugin.py
python tools/validate_sarm_20261012_platform.py --sdf-equivalence --reference-commit 662d829 --output run/perf-sdf/result.json
python tools/validate_sarm_20261012_platform.py --collision-equivalence --output run/perf-contacts/result.json
python tools/validate_sarm_20261012_platform.py --output run/perf-cycles/result.json
```

构建 UE 运行时后再进行真实页面预览与双相机采集验收；基础 CI 和静态接触比较不替代它们。运行数据、失败试验、截图、模型生成资产和编译产物保留在外部验收目录，不进入源码 Git。
