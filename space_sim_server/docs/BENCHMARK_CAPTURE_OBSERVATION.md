# 抓取公开观测与固定图像投递

`CaptureObservation` 把当前关节编码器与已到达的双目曝光分开。它是完整抓取环境的公开输入组件，尚不注册新任务或证明视觉闭环成功。相机像素来自环境的[运动挂载相机](BENCHMARK_ARTICULATED_CAMERA.md)，编码器来自[原生捕获臂读口](BENCHMARK_CAPTURE_ARM.md)；目标状态、相机世界位姿、接触真值和文件路径均不在公开契约内。

决策为 10 Hz，保留原双目的固定 200 ms 模拟投递时延。每次真实曝光附带该时刻的捕获臂编码器，不能把当前关节位置贴到两拍前的图像上。公开结构包含：

- `decision_time_ns` 和 `current_encoders`：当前决策拍及该拍编码器。
- `vision.sample_time_ns`、`vision.capture_encoders` 和两张原 PNG：同一次历史曝光及其关节读数。
- `vision.delivery_time_ns`：曝光加 200 ms，必须等于当前决策时刻。
- `vision_status`：前两拍为 `warming_up` 且 `vision=null`，之后每拍为 `delivered`，只包含当前到期的一对图像。

例如绝对历元 8000 s 起步：8000.0/8000.1 s 的方法观测没有图像；8000.2 s 得到 8000.0 s 的图像和曝光编码器，同时仍有 8000.2 s 的当前编码器。初始两拍只允许保持动作，不能提前消费尚在传输中的图像。

`CaptureObservationBuffer` 要求每拍按“完成真实曝光 → 发布一次决策观测”的顺序调用。它核对固定相机身份/尺寸、双目同会话/同帧/同时刻、10 Hz 连续采样和递增源帧编号，内部最多暂存三对图像，发布后最多两对等待投递。当前版本不模拟丢帧或重传；缺失、重复、未来曝光、会话替换或错配编码器会锁定失败，须重建回合，不能偷偷复用旧帧。新的传感器故障任务需另行声明故障模型。

`CaptureArmAction` 在原速度命令外绑定 `episode_id`、`observation_sequence` 和 `decision_time_ns`。`validate_for` 拒绝旧回合/旧决策动作及预热期运动，之后由环境将其 `command` 提交到原生绑定。动作身份、原生参考、实际执行器力与独立评分仍是不同记录。

reset 要重建缓冲区、原生核心、控制器和渲染会话；旧在途图像不跨回合继承。公开结构自身也校验时序和字段白名单，独立方法可通过 JSONL v2 接收其原尺寸像素。传输容量说明见[大图像方法接口](BENCHMARK_IMAGE_TRANSPORT.md)。

新增检查覆盖 8000 s 历元、曝光/当前编码器分离、前两拍无图像泄漏、固定延迟、重复/失序/会话拒绝、失败锁定、动作身份和新实例复位。它们使用合成小图验证时序，不代表实际 UE 或完整抓取任务验收；云端检查结果另行记录。
