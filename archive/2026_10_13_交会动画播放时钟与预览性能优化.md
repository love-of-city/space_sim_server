# 交会动画播放时钟与预览性能优化

## 问题与改动

基线 `320a0a9` 的交会每 0.5 s 仿真时间输出一帧状态。实测仿真约 4.54 倍速，状态约 9.08 Hz，收包间隔约 109–133 ms。原 UE 每次收包重置插值，窗口最多 100 ms，之后的外推直接把墙钟秒作为仿真秒使用，导致加速运行时动作快慢交替。浏览器请求的 90 FPS 也高于常见显示端实际呈现能力。

本次变更仅在 UE 显示端和前端预览配置：

- 引入连续播放时钟和最多 64 帧的有界缓冲。收包只更新速度估计，播放位置持续前进；用历史状态包围当前播放时刻，避免每包重新起算插值。
- 先平滑采样间隔，再估计仿真/墙钟倍速；以小幅速度修正消化收包抖动，外推预算按同一倍速换算，断流后不会无限预测。
- 首帧、重复时刻、回放跳转、长暂停恢复和 scene_reset 重建播放基准。原生测试覆盖 0.5、1、4.5 倍速、抖动、断流、长载入、重复帧与回退。
- 新页面默认选择部署支持范围内不高于 60 FPS 的最高档位；仍保留 90/120 等允许选项，本页重连保留显式选择。
- 删除旧双帧插值缓存的重复状态复制，接收到的状态直接转移进预览缓冲。

权威采集仍在预览插值前处理原始帧，严格队列、采样时间、模型、动力学、导航、控制与原始遥测均未修改。原地影、材质、卫星几何和相机视角不作减配。

## 同轨迹对照

使用已通过验收的 `35d363b3f98a49b8b128832c5494cf09` 记录，白昼追踪星近景，4.5 倍速、相同的 9 Hz 状态及确定性到达抖动；每轮预热后采样 20 s。回放只用于性能对照，不算新的物理飞行。浏览器为云端真实 Edge，原控制台和真实 UE/WebRTC。

| 指标 | 基线，请求90 FPS | 新时钟，请求90 FPS | 最终默认60 FPS |
| --- | ---: | ---: | ---: |
| 实际解码 FPS | 46.63 | 49.30 | 59.79 |
| 实际显示 FPS | 38.08 | 38.91 | 53.03 |
| 播放倍速中位数 | 4.481 | 4.488 | 4.486 |
| 播放倍速标准差 | 0.451 | 0.146 | 0.121 |
| 倍速 P05–P95 | 3.778–5.264 | 4.289–4.715 | 4.233–4.665 |
| 播放时刻倒退 | 0 | 0 | 0 |

最终默认配置相对基线：实际显示帧率提高约 39%，播放速度波动降低约 73%。UE CPU 从单核心基准的 702.8% 降到 480.9%，下降约 32%；这相当于总计约 7.0 核降到 4.8 核，不是机器整体 CPU 百分比。测得的改善只代表该控制条件，不保证所有场景或 RDP 网络下都达到相同帧率。

倍速统计由浏览器采样 UE 实际回报时刻，以约 200 ms 窗口计算；视频 FPS 来自实际帧计数，未把配置目标当成实际帧率。原始记录 SHA256 在三轮之间核对一致。中间版本曾把启动等待计入速度估计而产生追赶，已修复；中间记录 after-90 / after-60 保留，最终采用 after-90-final / after-60-final。

## 验证与复现

- UE 5.6 重新编译，33 项原生测试通过，包含原权威接收/采集队列和新增播放时钟测试。
- 前端 190 项测试和生产构建通过，覆盖帧率上限、60 FPS 默认值及用户显式选择。
- 真实交会终态接续、关节/键盘控制、急停/恢复、30 Hz 双相机各 137 帧采集、重置与停止端到端复验通过；另用新的短程交会验证原页面启动、取消、四视角与停止，短程任务不冒充完整验收。
- 最终逐项验收在工作区 `delivery/performance-acceptance.json`；原始日志、截图和 A/B 数据在 `validation/performance-optimization/`。完整交会仍以原始独立验收为依据；本次核对物理源码未变且原结果指纹继续有效。

工作区现有 `tools/check_cloud_browser.py --performance-only --recorded-flight <已验收目录>` 可在没有活动任务时运行同轨迹对照；`--performance-fps 90` 用于固定帧率 A/B。沿用原运行脚本启动云端平台，刷新原网页即可使用新默认值，手动帧率选项仍可用。

RDP 会额外进行桌面编码与传输。本轮没有取得用户本机的最终呈现帧时间，因此不声称已排除 RDP 链路造成的卡顿。状态缓冲会带来约 100–200 ms 的显示延迟，长停顿后直接恢复新收到的状态；这些处理不进入权威训练数据。
