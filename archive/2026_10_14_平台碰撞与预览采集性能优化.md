# 平台碰撞、预览与采集性能优化

本分支基于 main `4f1a321`（已包含 PR #18），集中移植此前个人分支仍适用的通用平台性能改进，并增加 SARM 导向孔的保守碰撞排除。保留上游最新 SDF 实现、批量渲染转换、六维测力与调度配置；远程交会功能没有作为依赖合入。

## 变更与保持的行为

- 新版 SARM 的螺纹杆完全处于导向孔内时，先证明外包圆柱与孔壁不相交，避免对确定无接触的杆/导向孔运行通用 SDF 搜索。检查整段杆轴的两个端点，加入杆最大半径、接触 margin 和浮点误差余量；倾斜、偏心或接近边界时回退原算法。只识别本插件 mode 2/4，其余碰撞对仍调用原函数。
- MuJoCo 的显式 pair 不经过 contactfilter，因此在注册本插件时通过公开 `mjCOLLISIONFUNC` 表包装 SDF/SDF 检测器。保持原检测器并逐对委托；不修改模型、碰撞矩阵、接触参数、SDF 采样数、积分步长、求解精度或距离/梯度算法。插件与现有加载器一样在进程内保持加载。
- BSK 引力仍按相同顺序调用原生逐刚体求值，只合并返回数组的转换；单位坐标轴 MRP 转换省去中间旋转矩阵。
- UE 预览使用连续播放时钟、有限缓冲与倍速感知的有界外推；权威采集使用原时间戳及状态。前端默认最高不超过 60 FPS，保留用户选择更高帧率的能力。
- Windows 小录制使用官方 LeRobot 原进程批处理编码，保留图像、统计和编码语义。另移植保存前将 shape-(1,) 标量转为零维值的 NumPy 2 兼容修复；大录制保留并行编码。
- 资源目录生成只提取 XML 中的网格／材质来源，不再编译物理模型。修复安装了独立 Python MuJoCo 的环境生成 SDF 场景目录时缺少插件而失败的问题，同时省去无用编译；仿真运行时默认保留原有网格中心补偿。
- 渲染启动遵循显式缓存参数、`UE-LocalDataCachePath`、原项目缓存目录的优先级，避免覆盖已配置的缓存。深层 checkout 可为整个启动进程设置一个较短的缓存路径，避免 UE 文件系统 DDC 的 119 字符根路径限制；仍保留 Zen 和持久化缓存。

圆柱包含判据的依据：螺纹杆的所有点都位于半径 12 mm、局部 z∈[-110,0] mm 的圆柱内。正交投影不增加截面圆盘半径；轴段径向距离的最大值由两端点给出。若该上界加保守余量小于导向孔半径 12.65 mm，两者的非正 SDF 区域不相交。检查每次使用当前姿态，无跨步姿态近似或缓存接触。

参考：[MuJoCo 3.7.0 碰撞分派与显式 pair 过滤](https://github.com/google-deepmind/mujoco/blob/3.7.0/src/engine/engine_collision_driver.c)、[SDF 接触生成](https://github.com/google-deepmind/mujoco/blob/3.7.0/src/engine/engine_collision_sdf.c)。

## 性能与物理等价验证

在同一 SpaceSim 云电脑，以 main `4f1a321` 和本分支交替运行相同 7 s 六轴运动、相同模型和初始状态。新主线默认 1 子步，环境力和运动学更新 stride 均为 8，双方保持相同配置。纯计算计时不包含启动、UE、网络等待和录制，不能等同于页面实际 FPS 或端到端实时性。

| 新 SARM / 默认 1 子步 | main 计算耗时 (s) | 本分支计算耗时 (s) |
|---|---:|---:|
| 第 1 轮 | 6.018561 | 5.222105 |
| 第 2 轮 | 6.264879 | 5.154346 |
| 第 3 轮 | 6.269523 | 5.441628 |
| 中位数 | 6.264879 | 5.222105 |

中位耗时减少 **16.64%**，计算吞吐提高 **19.97%**，计算实时因子 1.117→1.340。三轮各 210 个检查点的时间、qpos、qvel、qacc 逐元素完全一致。单轮补充检查：保留 5 子步时 18.350832→13.134723 s，同样逐元素一致；默认粗碰撞模型 3.125688→3.193541 s，同样逐元素一致，未证明默认模型提速。单轮结果仅作配置回归，不替代重复性能测量。

2880 组原生碰撞比较覆盖偏心、倾斜、轴向偏移、margin、反向 geom 顺序、轨道量级坐标及其他模式回退；原检测器产生 17070 个接触，完整接触输出零差异。926800 次距离和中心差分梯度比较与新主线逐位相同。构建器另外对原交付 SDF 做 100 万点比较，通过上游既有等价校验。

40 s 自由漂移与三次夹爪往复循环通过，最大耦合误差 2.91e-7 rad。这是稳定性回归，不代表完成自动抓取或插拔验收。云端真实 Basilisk 测力、引力、物理时钟专项 44 项及 LeRobot 双相机／测力记录回读 40 项通过；资源目录专项 5 项、缓存启动专项 4 项、UE 5.6 编译及 31 项自动化测试通过。

开发期间 PR #18 合入 main。此前 `662d829` 的 5 子步测量仅保留在外部历史试验中，不将上游减少子步或降低环境更新频率带来的收益计入本 PR。精细碰撞仍有成本，只有满足包含条件的无接触杆/导向孔对被跳过；靠近接触时继续承担原检测开销。

逐点精确缓存候选没有稳定提速，未采用。解析梯度候选即使单点梯度差异小于 1.6e-7，完整运动轨迹仍有明显偏差，已撤回；最终继续使用原 2e-6 中心差分，未放宽等价判据。

复现（在服务端目录，使用匹配 Basilisk MuJoCo 3.7.0 的已有 Python，输出选择新路径）：

```powershell
python tools/build_sarm_plugin.py
python tools/validate_sarm_20261012_platform.py --sdf-equivalence --reference-commit 4f1a321 --output run/perf-sdf/result.json
python tools/validate_sarm_20261012_platform.py --collision-equivalence --output run/perf-contacts/result.json
python tools/validate_sarm_20261012_platform.py --output run/perf-cycles/result.json
python tools/profile_simulation_runtime.py --adapter-root ../space_sim_UE_Adapter --scene-instance <同一个平台生成的场景实例.json> --model-path model/SARM/platform/sarm_20261012.xml --output run/perf-runtime/result.json --duration 7 --motion sweep_script --initial-state operating
```

主线与候选分别在新进程中加载各自的原生插件及 Python 实现，使用同一版 profiler、相同场景实例、模型和参数。记录计时配置、三轮交替结果和 `.physics.npz`；状态快照位于计时区间外。不要在吞吐测量时同时运行 UE 或打开额外性能计时回调。基准取自 `836023a`；之后的资源目录／缓存启动修复和注释变化没有改变上述动力学计算代码。

实机新版 SARM 的登录、连续视频、键盘控制、双相机采集、重置和停止已经验证。两路 RGB 各 222 帧、30 Hz，官方 LeRobot 读取器逐帧回读通过，独立视频解码同为各 222 帧，源帧编号递增，222 个腕部测力样本均有效且有限。已亲自检查真实页面和两路原始采集图像。录制数据归档传输后 SHA256 一致。该录制仅作功能验证，不代表抓取成功。

首次切换默认场景时，固定等待 8 s 的检查未获得视频，失败回执保留；切换复验以实际视频尺寸、就绪状态和连续帧计数作为依据，最终结果随 PR 的外部验收提供。运行数据、失败试验、截图、模型生成资产和编译产物保留在工作区 `validation/collision-performance-20261014`，不进入源码 Git。
