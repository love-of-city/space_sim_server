# 腕部相机彩色、鱼眼与黑白

网页在创建场景前提供三种腕部相机类型，默认彩色；运行期间锁定并随场景实例、复原和录制保存。Python 相机描述与 UE 协议一起增加 `camera_mode`，旧场景缺少该字段时使用彩色。

鱼眼采用 160° 圆形等距投影，UE 渲染宽视野，再通过独立 GPU shader 模块重投影，圆外留黑。中间图为输出长边两倍的正方形，最大 4096；这是理想镜头近似，不包含真实镜头标定、噪声或 180° 以上的覆盖。黑白使用 Rec.709 亮度并复制到三个 RGB 通道。两者保持原腕部 camera ID、RGB 产品和 1024×1024 输出，处理后的同一目标提供给 HUD、WebRTC、采集和策略观测。

采集协议补充镜头类型与等距内参；策略观测保留这些字段，并隔离调用方对内参字典的修改。修复网络预览请求误带默认磁盘输出标志，避免无输出目录时拒绝预览。

## 验证

- UE 5.6 Linux Development 编译通过；新增 `BSK.Protocol.CameraModes` 自动化测试通过（按导出的报告确认，NullRHI 的队列结束退出码为 1）。
- 服务端相关测试 104 个通过；适配器 Python 测试 99 个通过、5 个跳过、19 个子测试通过；前端 184 个通过并构建成功；Ruff 和差异空白检查通过。
- 独立真实 GPU 场景验证三模式：鱼眼显示 60° 针孔视场以外的目标，圆外留黑；黑白三个通道一致，且存在有效非黑图像。
- 现有真实 RGB 按需采集回归通过，包括开始/停止、两个 episode、在途复原与帧身份。
- 真实 SARM 场景鱼眼双路视频 `episode-20261020-160804-0da07482`，102 帧，`dataset_status=complete`；黑白双路视频 `episode-20261020-160848-28d15b4e`，122 帧，`complete`。解码腕部 MP4 检查鱼眼圆外黑色、黑白通道一致。
- 三种模式均通过独立页面的真实 WebRTC 预览验证：1024×1024、持续解码且画面非黑，鱼眼角落为黑、黑白通道一致。避免跨场景旧播放器残帧被当作新画面；旧连接在场景更换时可能需要点击重新连接或刷新网页。证据目录位于本机 `space_sim_server/run/camera-mode-acceptance/`；生成图像、视频、构建产物不入 Git。

## 部署

本机 UE 继续复用原安装，源码与 Python 描述同步到 `/home/lyh/space_enviroment/runtime/ue_adapter` 并重编译，前端重建、后端重启。其他机器必须同步更新服务端、Python 适配器和 UE 插件；旧 UE 会忽略新镜头字段。无需修改 enactive 仓库。
