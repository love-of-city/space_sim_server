# 仓库本地 Python 选择与 Conda 原生库加载

原启动脚本依赖显式参数、环境变量或已激活环境。虚拟环境迁移后，新终端可能选择其他解释器；直接调用 Conda 的 python.exe 时也可能缺少 NumPy/MKL 所需的 DLL 搜索路径。

解析器新增被 Git 忽略的 `.space-sim-python` 配置，优先级低于显式参数和 `SPACE_SIM_PYTHON`、高于已激活环境。只读取配置，不生成机器相关默认路径。检测到 `conda-meta` 时将所选环境的原生库目录加入当前进程 PATH，并保留原有模块预检与失败即停止行为。UE 端使用相同实现。

用户配置方法、优先级和恢复自动发现的方式见 [解释器说明](../docs/PYTHON_RUNTIME.md)。发布内容不包含本地配置文件、虚拟环境或包安装结果。

验证包括仓库现有解释器与启动脚本测试、基础 CI，以及在已有 Conda 环境中分别解析两个仓库并预检 NumPy。环境配置只影响后续启动的进程，不切换已经运行的仿真。
