# 地球 / 太阳星历与 UE 显示对齐（2026-09-07）

## 修复范围与原因

动力学初始轨道原本就是 500 km，但 UE 使用 `decorative_earth_position_m` 指定的固定背景地球。
该背景地心距离约 24,920 km、半径 6,371 km，视觉上相当于距其表面约 18,549 km。
运行场景只向渲染桥注册了太阳，没有注册动力学中的地球。
此外，`spicePlanetFrames` 被设为 J2000，混淆了惯性平动参考系与天体固连姿态输出。

本次没有改变轨道高度、机械臂参数、相机挂载或用户保存的场景实例，沿用地球/太阳两天体。
没有擅自增加月球及其他天体，也没有扩大重力源列表。

## 统一链路

```text
场景的仿真起始时刻 + 当前仿真时长
                  ↓
一个 SPICE 模块：地心原点、J2000 平动、IAU_EARTH / IAU_SUN 固连姿态
                  ↓
同一组 Earth / Sun 消息
          ↙                         ↘
Basilisk 重力                  bsk_render_adapter
                              减去卫星移动原点、转换姿态
                                        ↓
                          UE 地球、太阳、照明与地影
```

当前保存的场景起始时刻是 **2026-09-02 00:00:00 UTC**，不是机器的实时时钟。
推进仿真会推进星历；暂停/回放则使用相应仿真帧，不应单独使用墙钟更新某个天体。

### 服务端

`simulation/teleop_grasp_unreal.py`：

- `_create_ephemeris_interface()` 明确设置平动 `referenceBase=J2000`、`zeroBase=Earth`。
- `spicePlanetFrames` 改为 `IAU_EARTH`、`IAU_SUN`，输出真实随时间变化的固连姿态。
- `_register_celestial_bodies()` 注册与重力绑定的同一对 Earth / Sun 对象。
- 沿用星历 → 正向运动学 → 重力的已验证任务顺序，没有另外维护渲染轨道或重复积分天体。

地球没有作为巨大碰撞球体塞进 SARM MJCF；它通过天体协议传输，机械臂仍在本地尺度计算。

### UE

适配器工程 `Unreal/BskUnrealRenderer/`：

- `Config/bsk_unreal_scene.json`：`decorative_earth_enabled=false`。
  旧背景位置/半径保留为未启用的配置，不再决定平台场景的地球位置。
- `BskSceneController.cpp`：沿用星历地球的位置、姿态及半径创建和更新地球。
  现有逻辑也会在 manifest 含真实地球时隐藏装饰地球，避免双地球。
- 太阳显示仍使用近景代理以避免天文距离对 UE 特效/精度的影响，方向、视直径和姿态来自星历。
- 主视口太阳代理的可见性使用真实太阳/地球/观察点几何计算，而不是代理深度，避免地影中太阳
  因摆在相机前方 10 km 而错误出现在地球前面。
- `BskCelestialLighting.h`：加入球形天体的太阳圆盘遮挡计算，支持本影和角圆盘重叠近似的半影。
  局部物体的太阳直射光乘以可见比例。
- 天体表面使用单独照明通道，保留未被卫星地影衰减的太阳光；卫星进入地影不会导致整颗地球
  一起关灯。行星不进入米级机械臂的动态阴影图，地影由星历几何决定。
- 日志新增真实地球的半径、地心距离、高度，以及太阳未遮挡照度、局部照度和可见比例。
- 切换 manifest 时清理上一场景的星历太阳和遮挡状态。

## 验证边界

- 沿用原有曝光、材质环境项和太阳亮度标定。这不是绝对辐射测量标定；进入地影表示太阳直射
  消失，不保证画面中的机械臂变为纯黑。环境/材质显示项没有在此次移除。
- 半影采用角圆盘重叠近似，太阳代理在半影中做亮度衰减，不提供精确新月形日食轮廓。
  当前只验证一个地球遮挡体；未验证多个遮挡体同时交叠的完整遮挡面积。
- 太阳代理沿用既有主视口显示策略；辅助采集相机原本隐藏该近景代理，此次未将其改造为
  每台相机独立的太阳成像模型。地球姿态/位置与场景日照则共享同一权威帧。
- 使用 IAU 固连姿态，不宣称具备高精度 ITRF93/EOP 地理配准、大气辐射传输或恒星目录级成像精度。
