# 全局相机固定机位随机初始化

## 需求与行为

在已支持操作台位置/朝向随机化的开发分支上，增加全局相机 5 个固定候选机位的随机初始化。
每个新场景及每次自动采集尝试独立、等概率抽取；运行、载入和一键复原保持该机位。
机位固定在卫星本体上，并非惯性空间固定；P0 保留现有相机，P1/P2 为两侧斜视，P3/P4 为两侧高俯视。
具体坐标和使用方式见 `space_sim_server/docs/OVERVIEW_CAMERA_RANDOMIZATION.md`。

## 实现

- `overview_camera.py` 提供版本化预设、独立命名随机流、配置校验及实际 UE 外参核对。
  使用协议相机 +X 朝前/+Y 向左/+Z 朝上的坐标系，正确转换原 MJCF −Z 朝前的相机。
- 场景创建/API/网页保存严格布尔开关及完整机位记录。当前完整任务盒及其 SDF 版本支持；
  锁紧件特写 demo 和其它未标定模板拒绝启用。未启用及旧场景继续使用模型相机。
- 渲染组件直接覆盖原 overview 描述符的本体位姿，保持原相机 ID、采集格式、分辨率及采样率。
  相机由既有 UE 协议生成，不需要改动或重新编译 UE 插件。
- 自动采集网页默认勾选该项；API 省略时保持关闭；随仓库提供的并行采集配置显式开启。
  单批命令行提供正/反开关，并行配置及 API worker 将选择传递到每次尝试。
- 场景、attempt summary、episode metadata 保存机位和 seed。录制加载校验，不重采样。
  接受采集结果前逐帧核对 UE 实际相机外参，结合同帧卫星姿态和浮动原点变换，
  排除元数据与画面使用不同机位的记录。

没有修改源 MJCF、动力学或其它随机抽样流；保留此分支此前的布局、20 N 摩擦及 Linux 天光停顿修正。
未提交、推送或部署公网；前端已在此开发工作区构建。

## 验证

Python 覆盖种子复现、其它随机流不变、P0 与模型标定一致、协议轴向、5 个机位视野包络、
每次尝试重抽样、载入/录制不重抽样、元数据持久化、非法配置拒绝、实际外参不符拒绝、
API catalog 和 worker 配置传递。相关回归通过；Windows 进程专用测试在 Linux 正常跳过。
前端全部 185 项测试和 Vite 构建通过，Ruff 与 `git diff --check` 通过。

真实验证目录：`/home/lyh/space_enviroment/runs/overview-camera-presets-20261024/`。
使用实际共享 UE runtime，独立端口 24600–24603、同一随机布局和机械臂初态，
按 P0→P4 顺序复用一个 UE，逐条启动真实 Basilisk/MuJoCo 动力学与生产录制器。
各机位设置 3 秒仿真上限，验证双相机出帧、相机外参、完整视频解码和 50 Hz 时间间隔。
这些是有意截断的相机功能测试，任务结果应为 `total_simulation_timeout`，不计为成功训练数据。

最终验收数据及五机位实拍对比保存于上述目录的 `validation.json` 和 `five-camera-views.jpg`。
5 个机位各录制约 3 秒，分别为 152 / 151 / 151 / 152 / 151 对图像，合计 757 个数据帧、
1514 张配对图像。10 段 1024²/50 Hz 视频全部解码，逐帧实际相机外参核对通过，
无不完整或拒收样本。采集复用了同一个 UE，确认场景切换后实际使用新机位。
P3 高机位在本次机械臂初始姿态下存在部分前景机械臂遮挡；当前没有可见性自动筛选。
各布局的完整任务可达性、长时间动作中的遮挡仍需随正式采集验收，不能由短录制推断。
