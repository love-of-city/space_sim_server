# 航空螺丝初始孔的物理螺纹

`tools/bolt_storage_thread.py` 在平台派生模型中给初始存放孔增加一个内螺纹 SDF，
与原目标孔复用同一个已交付的 SDF 形状及接触参数。原始交付模型、螺丝自由关节、
初始位姿、质量与惯性、目标孔和机器人抓取几何均保留。

螺纹为右旋双线，导程 16 mm/转、单线节距 8 mm；内螺纹长 20 mm，外螺纹长
60 mm。默认初始外螺纹 SDF 上端比孔口高 2 mm，因此给初始内螺纹安装 −45°
相位来匹配初态。初始啮合长度 20 mm；螺丝尖端完全退出孔口需要上移 58 mm，
约 3.625 转。默认绕台面 +Z 正转对应向上旋出，负转对应向下旋入。

采集控制器的名义旋出目标为 58.5 mm（3.65625 转），并要求实际尖端越过
孔口至少 0.1 mm 后才进入搬运。不能将轴向落座容差用于提前宣告螺纹退出。
搬运会检查相差 180° 的两种等价双头螺纹相位，选择完整路径及后续旋入均
可达、无非预期碰撞的一支，避免腕关节累积转角走到限位。

目标孔的相位保持原样：默认螺丝本体高度 32 mm 时，需要相对原始螺丝姿态绕
台面 +Z 转 +45°（模 180°）。搬运后的旋入参考必须同时匹配旋转相位和轴向位置，
不能直接复制初始孔的角度。脚本通过多次松爪、回腕、重抓解决腕关节转角有限的问题。

初始孔 SDF 跟随 `bolt_storage_hole` 安装单元移动和转向，目标孔 SDF 跟随
`bolt_assembly_hole`。旧布局池模型在航空螺丝任务的 episode 模型生成阶段补上
相同物理内螺纹；预检、动力学和渲染使用这个派生模型。新增部分不使用焊接、
运行时姿态写入、假接触或额外的轴向吸附力。

2026-10-27 本机入口统一后，所有脚本任务都在共用的 `write_model_variant` 中
检查这一平台物理结构，不再仅为航空螺丝任务补齐。旧布局缺少母螺纹时，
在独立的 episode 模型补装；原布局、原始实验不改写。已有母螺纹必须与
存放孔属于同一个安装单元且有有效显式接触对，否则启动前拒绝。新布局
生成器也将初始孔和目标孔的母螺纹分别挂到各自安装单元，随位置和朝向
共同变换。锁杆专用初态仍只用于锁杆任务。

每条场景的 `collection_config.model_physics` 保存源模型 SHA、实际派生模型 SHA
和母螺纹的检查/补装结果。此统一不意味着旧布局池已按当前控制器重新通过
全任务碰撞验收；布局池既有 SHA 和轨迹门禁继续生效。

独立物理验收（独立进程运行，不能与 Basilisk 导入到同一 Python 进程）：

```bash
python tools/validate_bolt_storage_thread.py \
  --model model/SARM/platform/sarm_20261012.xml \
  --output /path/to/storage-validation.json
```

该验收使用同版本原生 MuJoCo、400 Hz 步长，并以同一点上的等大反向力/矩构成
试验夹具，检查静置、保持姿态时 5 N 直拉和带轻微轴向预载的旋出方向。
这是物理接口验收，不代表机械臂已经完成抓取、换抓和完整装配任务。
接触摩擦、柔度是沿用的仿真参数，尚未按真实航空螺丝标定。

锁杆任务另使用 `tools/threaded_task_initialization.py` 生成任务专用初态：
螺母沿原轴推进 4.79054 mm、旋转 1.881240659 rad；匹配的 MJCF `joint ref`
与本体初始变换使 `qpos0` 合法地表示锁住状态，旋松到坐标 0 仍恢复原始松开姿态。
该值根据原始凸碰撞几何的首次就位接触选择，避免把 0.18 mm 预穿透当作预紧力。
其他任务的锁杆初态和关节限位保持原样。

## 锁杆的真实卡扣接触

原模型的锁杆—底座碰撞排除也会作用到固定在同一焊接刚体上的卡扣，导致杆穿过
卡扣而没有接触。`tools/locking_cycle_contacts.py` 为锁杆与卡扣的凸碰撞体增加
960 对显式接触，保留原碰撞掩码。卡扣原始 CAD 带有收口，落座需要通过弹性卡口；
任务派生模型采用 `solref=".03 1"`、`solimp=".9 .95 .001"` 和切向摩擦系数 0.3
表示名义柔度。这是未经材料试验标定的弹性卡扣近似，不能解释为真实卡扣的刚度
或实测拔出力。不会关闭碰撞或在杆到达卡口时写入关节状态。

原底座碰撞凸包 `task_box_base_geom_collision_016` 跨过了原始 CAD 的凹槽，
会在杆约 −1.531 rad 时产生虚假挡墙。将它替换为原 CAD 材料与该凸包交集的
20 个精细凸分块；可视模型、质量、惯性和碰撞掩码保留。分块使用原始表面的支撑
平面，不按机械臂轨迹挖出通道。原始 CAD 在约 −1.64 rad 仍然会发生真实碰撞，
因此采集脚本的卡扣落座目标约为 −1.53 rad。只在锁杆任务派生模型中把铰链范围
扩展到 −1.75～+0.15 rad，使真实卡扣位置处于允许行程内。

分块资产及来源记录位于 `model/SARM/platform/mechanism_collision/`；
`locking_sweep_base.json` 记录源 MJCF、粗凸包和每个输出文件的 SHA-256、分割方法、
小于 2×10⁻⁵ 的总体积相对误差及丢弃的亚 0.1 μm 数值薄片。安装包含
`trimesh` 和 `manifold3d` 的几何环境后，可复建：

```bash
python tools/build_locking_cycle_collision.py \
  --source model/SARM/platform/sarm_20261012.xml
```

重复生成任务模型会更新已有接触及资产，不增加重复名称。旧随机布局文件若已经
重建底座、缺少上述粗凸包，暂不能套用这套精细分块；仍会恢复真实卡扣接触，
但必须重新预检底座干涉，或用更新后的布局构建工具重新生成。布局构建工具已把
锁杆扫掠包络覆盖到 −1.75～+0.15 rad；包络间距检查仍不等于机器人可达或任务成功。

独立锁杆接口验收：

```bash
python tools/validate_locking_cycle_contacts.py \
  --model model/SARM/platform/sarm_20261012.xml \
  --output /path/to/locking-validation
```

该验收在 400 Hz 下对机构施加明确标注的夹具力矩，检查拧紧后的阻挡、旋松后的
卡入、撤去驱动后的保持及再次抬起。夹具验收中，拧紧的杆在 −0.035 N·m 负载下
停在 −0.019 rad；松开后可卡到约 −1.515 rad 并重新抬起，螺母对底座穿透为零。
这些结果只验证机构物理接口，完整机械臂抓取、旋拧、放下和重抓仍需独立运行验收。
