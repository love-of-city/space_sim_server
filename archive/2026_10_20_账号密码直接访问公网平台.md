# 账号密码直接访问公网平台

原 Linux 公网部署默认要求账号登录后继续提供网址中的 `access_key`，导致普通网址登录成功后仍不能观看和控制。Linux 默认配置和示例配置现改为 `require_access_key: false`，当前机器的本地配置同步生效。登录会话自动授权视频凭据与控制连接。

部署构建子进程环境时清除继承自终端的旧 `SPACE_SIM_STREAM_ACCESS_KEY`；只有显式启用可选密钥校验时才重新注入。保留现有账号、角色权限、Secure/HttpOnly Cookie、Origin 校验和信令短期 JWT。兼容显式开启额外密钥的部署及原 Windows 部署行为。

更新访问命令输出与 Linux 文档，普通用户直接打开 `https://117.50.205.199/`。根 CI 部署路径过滤器已覆盖 Linux 模块、部署配置和部署测试，无需新增过滤规则。

- `tests/test_web_security.py` 与 `tests/test_linux_deployment.py`：62 项通过。新增回归覆盖无密钥登录、视频凭据、控制连接、注销后拒绝访问及清除继承密钥。
- 部署重启成功；启动流程的前端构建、信令检查和原生库检查通过。
- 使用真实 Chromium 从不含查询参数的公网网址登录 `lyh`，视频配置返回 200，操作 WebSocket 收到 session，腕部视频收到 25 帧且画面非黑；无页面异常。
- 未登录视频配置返回 401，操作 WebSocket 拒绝握手，无 JWT 的信令连接立即以 4401 关闭。
- 验证前确认没有录制或策略会话；重启后按相同模板、随机种子、相机模式、物理与采集配置重新启动场景，运行状态正常。这是重新启动场景，不恢复重启前的实时物理状态。
- `git diff --check` 通过。运行证据保存在被忽略的 `space_sim_server/run/account-only-acceptance/`，不提交账号密码、Cookie 或 JWT。

浏览器验证在服务器本机通过公网 HTTPS 入口执行；其他网络的媒体连通性仍取决于 WebRTC/TURN 可达性，本变更解决的是额外网址密钥阻挡。
