# J6 力矩上限对照（2026-09-28）

## 本次调整

遥操作入口 `simulation/teleop_grasp_unreal.py` 的 J6 力矩上限从
`±0.35 N·m` 提高到 `±0.70 N·m`，作为手柄转动顿挫问题的单参数试验。
其他五个机械臂关节和夹爪的力矩／力上限不变。J6 速度上限仍为
`0.5 rad/s`，Kp/Kd 仍为 `15/0.25`，参考保护、反作用轮、接触模型、
积分器和控制频率不改，也不启用原生姿态后端或线程池。

启动时 `teleop_control_configuration.arm_torque_limits_nm` 会记录实际限值；
既有的力矩遥测和饱和比例使用同一份上限。原始脚本场景
`model/SARM/platform/scenarios/scenario_sarm_grasp.py` 的默认值未修改；
遥操作启动时才将自己的参数传给原有 PID/力矩限幅链路。

这不是计算加速优化，而是**增大仿真执行器允许输出的力矩**。
权威物理引擎与积分链路未替换，但运动及接触作用力可能改变，
也不代表真实硬件允许输出同样的力矩。

## 离线 A/B 验证

使用保存的 `scene-20260928-104136-24d0d4e6` 的操作姿态副本，
在独立子进程中分别运行旧／新上限，不连接正式后端、UE 或采集系统。
保持 240 Hz 动力学、120 Hz 控制、RKF45 `1e-4/1e-4`，
仅注入直接 J6 指令（Cartesian IK 求解次数核对为 0）。

两组各推进 8 秒仿真：

- `0.5–3.5 s`：J6 正向 `0.5 rad/s`。
- `3.5–4.0 s`：松开。
- `4.0–7.0 s`：J6 反向 `-0.5 rad/s`。
- 其余时间为中立输入。

在 `1.0–3.25 s` 和 `4.5–6.75 s` 排除启动／换向瞬态后对比：

| 指标 | 旧上限 0.35 N·m | 新上限 0.70 N·m |
| --- | ---: | ---: |
| 正向角度增量／仿真时间 | 0.499992 rad/s | 0.499992 rad/s |
| 反向角度增量／仿真时间 | -0.499992 rad/s | -0.499992 rad/s |
| J6 保护锁止采样比例 | 0% | 0% |
| 跟踪保护降速采样比例 | 0% | 0% |
| 低于指令速度 10% 的采样比例 | 0% | 0% |
| 最大参考角度误差 | 0.022124 rad | 0.022124 rad |

在整个试验的 120 Hz 控制采样点，J6 实际力矩绝对值峰值约为
`0.280 N·m`，没有命令过期。30 Hz 探针采样最大接触数为 0。
这些不是每个 RK 子步的记录，不能据此断言任何子步都没有瞬时饱和。
8 秒仿真的带诊断执行耗时分别约 `24.366 s` 和 `23.889 s`；
仅各一轮且含诊断开销，不将这一差别称为明确的性能提升，也不是端到端画面帧率。

**结论：本次无接触、单独 J6 转动测试没有复现“饱和保护反复介入”，
增大力矩也没有带来可辨别的轨迹流畅度改善。**
之前将力矩不足列为首要原因只是推测，不能当成已确认结论。
本次结果也不能排除有接触、携带负载或混合多轴指令时的力矩不足。
前端卡顿仍需结合实际操作时的仿真耗时和画面传输验证。

更正此前的分析：J6 虽未单独写阻尼／摩擦属性，但继承了模型
`<default>` 中的 `damping="0.5"`、`frictionloss="0.05"`，并非没有阻尼／摩擦。
