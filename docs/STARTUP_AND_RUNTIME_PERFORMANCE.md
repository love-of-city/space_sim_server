## 启动保护

- 启动器在资产准备和 UE 启动前，使用 `tools/check_runtime_backend.py` 检查后端能力。
- 控制端口支持非侵入式 `capabilities_probe`，不占用仿真连接，不改变 reset generation，不断开当前仿真。
- 必须支持 `reliable_observations_v1` 与 `capture_ack_v1`；旧后端明确提示完整重启，不降级丢帧协议。
- 独立启动仿真 Python 时也必须先等 `observation_ready`，确认前不创建/推进物理场景。
- 公共健康检查只增加协议能力标识，不泄露运行状态、用户数据或凭证。

**代码更新后仍需完整重启后端和 UE；仅重新启动场景不能升级内存中的旧后端。**

## 计算优化边界

保持动力学 240 Hz、IK 120 Hz、权威 RGB 30 Hz。RKF45、误差容限、碰撞、姿态控制、
关节约束、肘部/手腕/第三关节偏好及数据可靠性均保持原配置。

1. 串联运动学中，关节固定轴的归一化、反对称矩阵及平方项只在构造时计算。
   每个新姿态仍按原 Rodrigues 公式计算，矩阵相乘顺序不变。
2. 姿态偏好解析梯度改为按祖先关节批量叉积，消除多次小数组分派；不降低求解次数，
   不缓存过期状态，外部 API 仍返回独立数组。
3. UE Python 适配器的 3x3 旋转矩阵检查消除通用 `allclose/isclose` 分派开销；
   正交性、正行列式、有限性及原来的误差阈值全部保留。

## 验证方法

- 随机姿态、任意上方向、非零关节偏移与原始算法比较。
- 原始与优化后的原生仿真，对比每一行关节状态、目标、末端位姿、动作和时间戳。
- 同一场景、20 秒仿真时间、持续 0.006 m/s 平移动作，以 before/after/after/before 顺序
  运行不带 profiler 的计算基准。before 在独立进程加载保存的原始数学实现，不修改仓库或生产服务。
- 计算基准排除 UE、网络和录制，因此另用真实 UE + Basilisk + 官方 LeRobot 进行双相机录制。
- 诊断产物位于 `run/runtime-repair-20260923/`，不写生产 episode 目录和认证数据库。
