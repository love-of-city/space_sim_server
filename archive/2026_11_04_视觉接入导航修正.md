# 双目视觉不确定性与导航接入修正

## 触发问题

PR #41 的已有验收是 CLI 远距记录通过后，由正式协调器接续近距并完成四爪抓持。随后从 HTTP 正式入口、7 km 起点重新连续运行，任务在 `OriginalStereoAcquire` 节点等待视觉就绪超时。这两次运行分别保留，先前通过的结果不能代替本次运行。

失败轮 `477d2c995f6b41c3887f1afef92d9d7d` 共处理3401组双目照片，最后左右眼均使用 ID 0–3，角点拟合通过。导航记录中只有2次视觉更新被接受，1215次被创新检查拒绝；最终任务进入 SafeHold，未到0.5 m平台，未执行最终抓持。

## 修正

`visual_navigation.py` 现在集中提供 `visual_pose_covariance()`。视觉就绪门槛和
`PoseNavigation.visual()` 使用同一套位姿协方差约定及光学深度不确定性门槛；对
Near23 眼在手上的观测，检查导出的光学深度标准差，而不是把旋转后的服务星本体
坐标 Z 方差当作光学深度。超出门槛的观测不会进入导航滤波器，也不会增加视觉就绪计数。

相机、靶标、灯光、模型、动力学积分、真实图像 10 Hz 采样及 0.2 s 仿真交付参数均未调整。
这次修正没有实现非线性 MAP 迭代，也没有使用仿真真值喂给导航。

## 验证状态

- 使用项目测试解释器复跑视觉导航和 Near23 导航回归，63 项通过；修改的四个 Python 文件通过 Ruff。回归覆盖协方差门槛、光学深度检查及拒绝观测时的状态保持。
- 连同正式入口、连续审计、V-bar 序列及末端抓持评分的相关回归共 118 项通过（包含上述 63 项）。
- 固定失败轨迹的离线重放中，接受视觉观测由 2 次增加到 1185 次，32 次因不确定性超限被拒绝。重放使用近似重建的初始协方差，不能替代实际动力学全流程验收。
- 新的 HTTP 从 7 km 起点连续任务录像仍是失败记录：近距视觉接入超时，未到 0.5 m 平台，也未执行最终抓持，不能作为整段通过证据。

运行数据、视频与诊断脚本保留在本地 `run/`，不提交仓库。新轮来源以源码 SHA256 和具体任务编号为准，不能把修改后的工作区标为与已合并 main 完全相同。
